# PUSH-013 推送候选内容与文案准入流程

资料性质：原创模拟业务手册；公开规则段落为官方资料的简短转述。非任何公司的内部文档或真实事故记录。
适用对象：推送业务示例部门的同组研发与相关业务方同事。版本：2026-10-24。

## 审核与发送是两个流程
候选内容或推送文案被接收，不代表已审核通过；审核通过也不代表已发送或终端已展示。业务状态应能区分待审、通过、不通过、停用等含义，并记录适用版本。这里只定义模拟协作流程，不给出任何公司的审核政策。
## 机器审核与人工审核衔接
模拟链路先接收候选与文案版本，再按适用策略进入机器审核；需要人工判断的材料进入人工环节。审核结果要与当时内容版本绑定，文案修改后不能沿用旧版本的通过结论。通道发送凭据和审核权限应分开管理。
## 不通过与撤回
不通过内容不能进入后续准入；已通过后发现风险时，按授权维护停用或下线状态，并保留原因、操作者和版本证据。是否还能阻止已经发给外部通道的通知取决于实际系统能力，不能承诺已发送内容可以全部追回。
## 业务方查询
同事问“为什么这条没推送”时，先确认候选与文案版本、当前准入结果和发送证据，再解释处于哪一阶段。知识助手只给流程说明和检查入口，不直接修改审核结论，也不捏造风险识别准确率或历史漏放数量。
