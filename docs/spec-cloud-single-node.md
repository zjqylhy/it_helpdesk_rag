# 阿里云单机部署与验收规格

## 已确认需求与当前状态

- 用户确认先完成单机云部署与验收，并迁移当前本地 Docker 的知识库和历史记录。
- 使用一台 Linux ECS，Go、RAG、Web 和 PostgreSQL/pgvector 由 Docker Compose 管理；宿主机 Caddy 提供 HTTPS。
- 沿用业务代码、模型配置和权限行为，不引入 RDS、OSS 或多实例。
- 截至 2026-10-11，用户尚无 ECS 和域名。地域、预算、SSH 连接和公网域名待提供；实际云部署未开始。
- 需求范围与单机技术路线已确认；实际账号、地域和资源购买配置在创建付费资源前由用户确认。云端测试完成后仍须用户确认页面与问答结果。

操作命令沿用 [云部署说明](cloud.md)，本文件明确迁移顺序、验收标准和未完成项。

## 资源与入口

初始容量估算为 x86_64、2 vCPU / 4 GiB 内存、60 GiB 云盘，Linux 建议 Ubuntu 24.04 LTS。该估算不是压测结论；首次部署观察内存、磁盘与问答延迟再调整。模型通过外部 API 调用，不需要 GPU。

- ECS 具备 SSH 管理入口和访问模型 API、镜像仓库及依赖下载源的出网能力。
- SSH 使用密钥，22 端口限定管理 IP；域名就绪后开放 80/443。
- Web 保持宿主机 `127.0.0.1:3000`，数据库保持宿主机回环地址，Go/RAG 不发布宿主机端口。
- 暂无域名时，通过 SSH 转发进行受控预验收，不把明文 HTTP 登录入口公开到公网。示例：`ssh -N -L 13000:127.0.0.1:3000 用户@ECS公网IP`，浏览器访问 `http://127.0.0.1:13000`。
- SSH 预验收不能替代公网 HTTPS 验收。正式入口使用受控域名，配置解析、证书及 Caddy 开机启动。
- 中国内地网站上线前完成适用的 ICP 备案；香港或海外节点的 ICP 要求不同。地域由用户确认。
- 在用户确认地域、计费方式与费用上限前，不购买实例、域名或其他云资源。

参考：[ECS 创建说明](https://www.alibabacloud.com/help/en/ecs/quick-start)、[计费说明](https://help.aliyun.com/zh/ecs/pay-as-you-go-1)、[备案要求](https://help.aliyun.com/zh/icp-filing/basic-icp-service/user-guide/icp-filing-server-access-information-check)。

## 发布与配置

1. 使用已提交且工作区干净的版本，记录 commit 和镜像版本。当前准备分支为 `codex/aliyun-single-node`；实际发布时重新记录 HEAD。
2. 目标目录建议 `/opt/it-helpdesk-rag`，Compose 项目名固定为 `it-helpdesk-rag-cloud`，所有启动、备份和恢复命令均使用同一项目名。
3. 建立云端独立 `.env`，替换数据库密码、演示账号密码和内部令牌；只迁移所需的模型配置，凭据不写入 Git 或验收报告。
4. 验证 `docker compose -p it-helpdesk-rag-cloud config --quiet`，设置 `APP_REVISION` 后构建。若下载受限，使用受控镜像交付方式；不取消依赖版本和哈希校验。
5. 初次只启动新空数据库，恢复数据与文件之后再启动应用，避免应用预先创建业务数据。
6. 无域名先执行 SSH 预验收；域名就绪后验证 Caddy 配置并由系统服务管理，检查重启后入口仍正常。

## 完整迁移

2026-10-11 本轮只读检查本地 `it-helpdesk-rag-docker`：四服务 healthy，8 个知识库、10 份文档、721 个切片、13 个会话、19 条消息；排队/处理中导入任务与生成中消息均为 0。这是准备时快照，正式备份前必须重新采集。

1. 在迁移窗口核对无在途任务，停止本地 Web、RAG、Go 的写入，保留数据库运行。导出数据库与上传卷后恢复本地服务。
2. 每次使用独立目录保存同一批次的 dump、上传文件归档、文件 SHA256、表数量和源代码版本；Windows 使用二进制安全的输出方式。
3. 不直接使用 `data/docker-validation/rag.dump` 等旧验证备份作为最新迁移源；它们不代表当前完整数据库。
4. 通过加密传输复制到全新目标实例，核对归档 SHA256。在目标空库恢复 dump，恢复上传文件，设置 UID/GID `10001:10001`。
5. 保留原有知识库、文档、版本、快照、会话及消息 ID；保留 `/data/uploads` 路径、1024 维向量和权限关系，无需重新生成 Embedding。
6. 目标 `.env` 设置管理员/演示账号新密码。清空目标数据库中恢复的登录令牌，要求重新登录；不修改源数据库令牌。
7. 启动全套服务，核对迁移基线和业务流程。验收过程中新增的数据单独记录，不与恢复前基线混算。

## 验收标准

| 类别 | 通过条件 | 证据 |
| --- | --- | --- |
| 发布版本 | 目标运行版本与发布 commit 一致；四服务健康 | commit、镜像版本和服务状态 |
| 数据完整 | 表数量与备份基线一致；原 ID、权限关系、历史消息及引用保留 | 迁移前后数量与 ID 对比 |
| 文件与向量 | 每份原文件 SHA256 与数据库记录一致；原有向量维度与切片数量一致 | 校验汇总 |
| 登录与权限 | 新密码登录正常，旧令牌失效；普通用户不能访问未授权文档，撤权后历史依赖按现有规则遮蔽 | API 与页面结果 |
| 上传导入 | 专用验收库上传测试文档，任务完成，切片与版本可查看 | 任务、版本和切片结果 |
| 问答与引用 | 指定库问答、联合问答、学校澄清承接正常；流式显示、引用及原文件下载可用 | 问题、结果、引用及页面人工确认 |
| 模型协议 | 云端 Embedding、Rerank、DeepSeek JSON 与流式探测通过 | `helpdesk.probe` 脱敏输出 |
| HTTPS | 域名解析正确，浏览器证书可信，HTTP 跳转 HTTPS，公网流式响应无意外缓冲或超时 | 外部请求和浏览器结果 |
| 持久化 | 重建应用容器及主机重启后，数据、文件与 HTTPS 入口可恢复 | 重启前后检查 |
| 备份恢复 | 云端数据库/文件成对备份，在隔离空实例恢复成功，数量和校验一致 | 独立恢复结果 |

真实模型探测最多五次 HTTP 请求；业务验收另有少量真实模型调用，记录请求和用量。未重新执行完整正式质量评测时，不宣称云部署已经复现全部离线成绩。

当前 Go 问答上下文和服务写超时为 120 秒，Nginx 读取超时为 600 秒。云端实测记录首段响应和总耗时；若出现超时，先定位链路并提出调整，再实现和验证，不能仅调代理超时。

## 回退与验收记录

- 云端验收完成前保留本地原实例和本轮备份，不删除卷、不覆盖已有业务数据库。
- 失败时停止目标应用，保留现场和脱敏日志；新空目标可重新恢复。失败的云端不接收正式业务写入。
- 若云端上线后已经产生新数据，回退前先备份目标实例，避免直接恢复旧库丢失新写入。
- 私有备份、会话内容、凭据和含业务数据的测试报告存于忽略目录或受控位置。仓库只记录脱敏数量、版本、校验结果和通过/失败状态。
- 部署报告逐项标记通过、失败或待执行；公网 HTTPS 和用户人工确认未完成时，不标记整体验收通过。
