3. 复用九个原知识库标识，先上传十八份新文档，保留默认管理员可见范围。记录上传回执，重复执行先识别既有文档，不重复上传。
4. 确认十八个任务完成；通过下载接口逐份核对原文件 SHA256，核对 213 个切片的文本 SHA256。再通过正式授权接口向应用内已登录成员开放这些非敏感示例资料。
5. 通过正式文档启停接口停用原十一份资料，保留原文件、版本、切片与历史。维护事务只对计划内九个知识库参数化更新名称、组织、默认检索开关，不变更结构或账号。
6. 普通成员 API 验证仅可见十八份新资料，旧资料不可见；活动且启用的切片总数为 213。原十一份文件哈希均与切换前一致，目前合计 29 份原文件/文档。

旧资料在管理员的知识管理历史中仍可见，状态为停用；管理员保存历史不意味着它们仍进入新问答检索。原授权关系没有扩大，新资料不含公司资料、真实设备标识或凭据。
