# 问答断连恢复需求规格

日期：2026-10-23。状态：需求已确认，技术方案待确认，尚未开始实现。

## 目标与确认记录

用户预期支持“切走页面、短暂断网，回来继续看”。2026-10-23，用户在需求草案及上传恢复讨论后明确表示：“我没问题了，进入技术方案阶段吧”。上传与入库恢复的问答用于解释现状，不扩展本次开发范围。

用户离开页面或短暂断网后，已经受理的问答继续执行；返回后查看同一次查询的进度和结果，不重新提问、不因重连重复调用模型。

## 行为要求

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| R1 | 切换页面、会话，关闭标签页 | 已受理的问答继续执行，允许界面切换会话 |
| R2 | 刷新、重新打开会话 | 自动恢复该问答展示；若已完成，直接展示完整答案和引用 |
| R3 | 短暂断网 | 显示连接状态，不把网络故障当成问答失败；网络恢复后自动重连 |
| R4 | 返回时仍在生成 | 补齐已生成内容，继续更新；全文不重复、不遗漏，标明正在生成 |
| R5 | 明确点击停止 | 取消该问答及上游模型请求，显示已中断 |
| R6 | 超时、执行失败、相关权限撤销 | 结束任务，显示对应状态；无权查看时遮蔽正文和引用 |
| R7 | 提交回执丢失或重复提交 | 同一会话、同一请求编号只执行一次；同编号不同问题明确报冲突 |
| R8 | 无人订阅 | 仍受原有任务时限、模型调用和用量限制，不无限执行 |

## 范围边界

- 本期支持浏览器连接中断后的恢复；不要求保留逐字回放过程，只要求当前正文完整、后续继续更新。
- API 服务重启后，未完成问答标记中断，不自动重新推理；不实现服务端断点续跑。
- 不新增跨设备恢复的产品承诺，不扩展为多 API 副本部署。
- 不修改上传、文件断点续传、入库 Worker 重试或入库检查点。
- 不修改检索策略、模型选择、提示词或事实质量门禁。
- 未完成草稿不作为完整答案或下一轮的知识证据；主动停止、失败时沿用当前清空草稿的规则。

## 验收标准

1. 用慢速模型替身生成答案，中途关闭页面，再打开原会话：后台执行一次，恢复全文并继续更新，最终答案与一次正常执行相同。
2. 网络离线后恢复、页面刷新、会话切换、重连时恰好完成，均不重复创建消息或触发模型调用。
3. 多次重连后文字不重复、不缺失；最终状态和引用与数据库一致。
4. 点击停止后，上游连接关闭，后台不再执行后续步骤；重复停止可安全处理。
5. 权限撤销后，无论任务是否有订阅者，都停止受影响的执行；重连和历史访问不能取回无权内容。
6. API 重启后不自动重做问答；用户能看到中断状态并自行重新提问。
7. 恢复连接不重置任务时限或模型预算；断连状态下仍能正常超时和结束。
