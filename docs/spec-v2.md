# 第二阶段需求规格：质量、工程、反馈与权限

日期：2026-10-10

状态：四项范围及资源条件已确认；本文细化规格与配套技术方案待人工确认，尚未进入本阶段应用代码实现。

## 1. 目标与边界

用户确认补齐：跨库正式评测和失败分析、本地工程验证与云部署方案、完整业务闭环及真实反馈指标、用户组加文档权限。

- 继续使用 Go、Python、Vue、PostgreSQL/pgvector，兼容 Windows 原生开发和 Docker Desktop。
- 尚无云服务器及域名，本轮完成本地压测、故障与恢复验证、可部署配置和云验收清单。真实云部署、域名证书和公网验证标为待资源，不计为已完成。
- 保持单 Go、单 RAG 实例；不承诺多副本、高可用、100 QPS 或 99.9% 可用性。
- 不包含企业 SSO、知识源自动同步、OCR、飞书机器人或自动建工单。
- 原始文档、问答、反馈明细和评测材料继续本地私有保存；不提交密钥或原始内容到 Git。
- 本文在第二阶段范围内扩展 spec-v1；首期历史成绩和冻结集保持原样。

## 2. 跨库评测和失败分析

### 2.1 拟定规模与流程

保留原 test-200-v1；新增 scope-dev-20-v1 和 scope-test-60-v1，数量待本次方案确认，不将增量 60 题称为原 200 题的替代。

| 正式增量场景 | 题数 | 重点 |
| --- | --- | --- |
| 明确组织、默认全库与指定单/多库 | 20 | 正确选库、无关库干扰、同名术语 |
| 跨组织比较与跨库证据组合 | 12 | 分别归属来源、不混用条件；每题必须有真实业务意义 |
| 多轮澄清和组织切换 | 10 | 指代承接、切换后不沿用旧组织 |
| 应澄清问题 | 10 | 缺少组织或必要条件，不提前编造步骤 |
| 应拒答或说明冲突的问题 | 8 | 未收录组织、证据不足；确有冲突才出冲突题 |
| 合计 | 60 | 每题仅归一个主要场景 |

- 开发和正式测试按事实主题隔离，与原开发集检查主题重叠；跨库题必须审核必要证据和题目自然性，不用无关事实拼凑题量。
- 与原 200 题共享事实主题时明确披露，报告题数及唯一主题数；不能将两套结果相加宣称有 260 个独立样本。
- 当前素材不支持的场景在审核前调整分配并披露，不编造文档或隐瞒覆盖不足。
- AI 只生成候选；用户审核题目、必要事实、证据及预期行为后冻结。首轮 60 条实际答案也全部人工裁决。
- 单独构造权限安全测试夹具；虚构夹具用于验证权限，不计入真实知识效果指标。
- 记录语料/数据集/权限夹具校验值、快照成员、模型、策略、代码版本和逐调用用量；可复现及断点续跑。
- 正式集不能用于调 Prompt；失败原因在报告中保留，改进先在开发集验证，另报重放成绩。

### 2.2 指标和验收

- 分场景报告：组织路由正确率、必要证据 Recall@5、可回答题正确率、澄清/拒答正确率、比较对象证据覆盖、引用合法性和人工引用支持判定。
- 模型评分与人工裁决分开；错误、超时、中断及评分失败保留在对应分母。澄清/拒答场景不强行按必须召回证据计算 Recall。
- 质量目标沿用可回答题正确率 ≥85%、Recall@5 ≥82%；引用合法率和权限安全检查要求 100%。其他指标报告实测值，不预先承诺达标。
- 报告逐题失败归因：理解/路由、解析、召回、重排、上下文截断、生成、澄清/拒答、引用、权限、运行故障；允许主因与次因并存。
- 不以原 qa-v2 的 90% 代表当前跨库质量。需要旧/新策略对比时使用同一增量数据集、语料及权限，不能比较两个不同集合的总体百分比。

## 3. 本地工程验证和云部署准备

- 增加请求标识、阶段耗时、模型故障类别、排队/在途请求和用量观测；日志不记录密码、Token、Key 或默认输出问答正文。
- 登录和问答限流、问答全局在途上限与有界等待、请求取消/截止时间；过载明确拒绝，不无限等待。
- 支持可配置的用户每日问答请求配额及服务每日模型调用配额；拒绝、重试和取消的计费口径明确记录，Token/金额用量不齐时不能声称严格金额限额。
- 增加模型短期故障熔断，重试仅在安全且有预算时发生；流式失败保留中断状态，不能把错误文本标为完成。
- 本地用替身模型进行 1/5/10/20 并发阶梯压力测试，每档至少 100 请求，包含 SSE、取消、幂等、权限和过载。记录机器资源、运行时间及完整样本，区分容量问题与外部模型限额。
- 真实模型验证 1/3 并发各 10 个请求，记录实际调用和费用估算，不以替身吞吐宣称真实模型吞吐。
- 验证模型限流/超时/坏响应/流式断开、RAG 重启、Go 重启、导入任务恢复、数据库短暂不可用等场景，正常业务能够恢复且无重复完整答案。
- 对完整业务语料、文件、权限、反馈和会话做成对备份，在独立实例恢复并核对数量、内容校验值与抽样业务流程；记录恢复耗时，不覆盖当前实例。
- 云说明包含配置、HTTPS 入口、端口边界、监控、升级/回滚、备份恢复和资源到位后的验收步骤。本地容器通过不等于实际云端通过。
- 浏览器与服务端分别报告首字/完整回答 P50、P95；样本数和失败数同时展示。既有 2 秒/5 秒为优化目标，未达目标如实记录。

## 4. 反馈、修复闭环与业务看板

### 4.1 反馈和人工处理

- 普通用户只能反馈自己的已终结回答，支持补充原因。质量判断与问题是否解决独立记录，不能用“不满意”自动认定事实错误。
- 完成、拒答、澄清均可反馈；生成中、错误和中断在工程指标统计，不混入完整回答的反馈分母。
- 同一回答保留一条当前有效反馈；修改或撤回追加历史事件，重复请求幂等，不重复计数。
- 管理员复核用户主动反馈的回答及其证据，记录正确/错误/无法判定、原因和处理状态；不因此开放所有用户会话浏览权限。
- 闭环为：反馈 → 人工复核 → 问题归因 → 文档/策略/产品修订 → 回归证据 → 结案。无法复现及非错误反馈分别标注，不能当作已修复错误。
- 多条反馈可关联同一问题，避免重复问题膨胀修复率；结案需有修订版本/commit 及验证记录。问题可重新打开，保存全过程。
- 反馈可生成评测候选，人工审核后发布新版本；不得自动覆盖原标准答案、冻结题或用户原反馈。

### 4.2 指标定义

看板首版仅管理员可见，默认最近 30 天，可按时间和策略版本筛选。回答以创建时间归属统计周期；反馈采用查询截止时的当前有效状态；历史变更支持审计。日期边界使用明确时区。

| 指标 | 分子 / 分母 |
| --- | --- |
| 反馈覆盖率 | 有有效反馈的不同回答数 / completed、refused、clarify 回答总数 |
| 用户报告解决率 | solved 数 / 有 solved 或 unsolved 反馈的 completed、refused 回答数；clarify 不计解决率 |
| 错误报告率 | 有效质量判断为 incorrect 的回答数 / 有有效反馈的回答数 |
| 复核确认错误率 | 确认错误的回答数 / 复核结论为正确或错误的回答数；另列无法判定与待复核数量 |
| 问题修复率 | 已修复且有验证证据、当前已结案问题数 / 已确认错误问题总数；按唯一问题计算 |

- 每项展示分子、分母、周期和口径，分母为零显示“暂无数据”，不显示 0% 或 100%。
- 展示解决状态和质量判断的填写覆盖情况；用户报告解决率不等同于客观工单解决率，反馈样本不代表全部回答正确率。
- 区分真实用户使用、开发自测、演示、工程压力测试和离线评测。来源由服务端账号/运行上下文确定，普通客户端不能自行切换。
- 现有演示账号及自动化测试默认不进入真实指标；管理员将实际参与者账号设为真实使用前明确记录来源，测试记录不能事后提升为真实使用数据。
- 无真实使用数据时展示空状态；可以切换查看有明显标识的测试数据，不自动补造反馈或业务提升数字。
- 已结案不自动将原用户反馈改为“已解决”；复核和修复结果分别展示。

## 5. 用户组与文档权限

- 管理员可管理普通用户、停启账号、用户组、组成员以及文档可见性。企业 SSO 留后续。
- 文档可见性为“所有已登录用户”或“指定用户组”；多个组取并集，未授权默认拒绝。管理员可管理及读取全部文档。
- 新文档默认仅管理员可读，授权后普通用户才能查询；新版本继承文档当前权限，旧版本不保留过时的授权。
- 迁移现有文档为明确的“所有已登录用户”权限，保持已授权演示用途，并记录迁移审计。此规则待本次方案确认。
- 普通用户仅看到包含其可读文档的知识库；默认全库、指定库、组织澄清选项只基于当前可见内容。不用不存在和未授权的不同提示泄露文档存在性。
- 文档列表、版本、切片、原文件下载、检索、模型上下文及引用均校验权限，不能仅前端隐藏或生成后过滤。
- 已撤销权限的旧回答可能包含派生信息。再次读取时整体遮蔽依赖受限文档的答案、引用、trace 和自动来源元数据；保留用户自行输入的问题及“来源权限已变更”提示。
- 追问不得向模型发送已经失权的旧答案或其来源。权限变更需失效相关索引缓存/授权缓存。
- 在途生成于权限变更时中止，并停止后续输出；撤销确认后的后续请求和流片段不得返回旧权限内容。已发送到浏览器或外部模型的内容无法追回，不能声称具有这种能力。
- 安全测试覆盖同库内不同文档权限、无权限 ID 猜测、跨库比较、历史、下载、撤销、移出组、账号停用，以及缓存和在途生成。

## 6. 实施顺序和人工节点

1. 确认本文和技术方案，含增量评测规模、历史文档迁移和撤销语义。
2. 权限基础与端到端负例测试，保护后续数据采集和评测链路。
3. 反馈、人工复核、修复状态及指标看板，人工验收页面与口径。
4. 工程观测、限流、压力/故障/恢复验证和云部署准备。
5. 跨库开发与正式候选审核、冻结、真实运行、失败分析及实际答案人工裁决。

每批改动验证后提交 commit。未完成资源相关验收或真实数据积累时，保留明确待完成项，不将“功能可用”当作“业务效果已经产生”。
