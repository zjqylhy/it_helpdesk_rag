## 1. 数据和方法

- 数据集：`test-200-v1/windows/cases.jsonl`，30 条多文档题均来自 Windows 库。
- 答案及裁决：`reports/test-200-v1/human-reviewed-D/cases.jsonl`；重算人工通过 22/30。
- 生成清单：`reports/test-200-v1/end-to-end/windows/D/manifest.json`；生成 commit 为 `1eac3740de7e0886e4cca9b51577657fe35230e6`，提示 `qa-v2`，上下文预算 8000 字符。
- 生成模型为 DeepSeek，Embedding 和重排为 Qwen；具体模型标识以原清单为准。本次诊断不代表当前模型网关或 `qa-v3-scope` 的效果。
- 对冻结的每个证据组逐一核对文档版本、段落/章节和字符区间。组内任一锚点覆盖即可，组间必须全部覆盖；重叠切片合并区间，不重复计数。
- 分别检查 BM25 Top-20 与向量 Top-20 的候选并集、RRF 后 Top-20、实际上下文 Top-5。30 题的上下文锚点召回均与保存的逐题指标一致。

这里的“缺失”首先指冻结锚点未覆盖，不直接等价于没有任何语义等价证据。答案归因还结合实际上下文和已确认的逐事实裁决。

## 4. 优化选择

先补各阶段观测和独立跨库开发题。第一项受控实验拟选择“复合问题查询拆解”：主因 5/8 出现在候选召回，单纯调整 Top-5 分配无法找回候选池之外的证据。

实验只改变查询拆解和由此必要的多查询候选合并；模型、重排、证据上限、字符预算、充分性判定及答案提示固定。开发结果若没有改善则保留负结果，不在同一正式集上连续试多种策略挑最好结果。去重/证据分配列为后续独立实验，不与第一轮同时改动。

旧 30 题已用于诊断，只能作为历史回归，优化后的重放不能包装成新的盲测成绩。完整原文、答案及审核材料继续留在私有目录，公开文档只包含 ID、阶段位图和汇总结论。
