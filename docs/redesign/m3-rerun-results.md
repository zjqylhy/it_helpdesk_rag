## 错误、行为与费用口径

本次客户端逐调用记录**没有 429**。3 条错误尝试分别为：

1. split-v1 / 003：拆解 `invalid_provider_response`，已知输入 163、输出 2048 Token；按原协议回退原查询，不重放拆解。该题最终完成生成。
2. split-v1 / 003：Embedding HTTP **503**，受限 request-id 已保存，输入用量未知；非流式在原预算内重试一次并成功。未知用量没有填 0。
3. baseline / 002：`incomplete_generation`，已知输入 699、输出 **2048 Token**；生成流不重放，整题为 error，部分正文不冒充最终答案。前序各检索阶段的证据组召回均为 1。

两条未完成/无效输出调用均报告 2048 输出，碰到冻结的最大输出数，但没有保留足够的原始响应信息来证明具体截断机制；此处不将推测当作已确认根因，也不临时调高输出上限补跑。

split-v1 / 002 在黄金预期 answer 的题上返回 clarify，是需人工核对的**行为不匹配**；是否属于错误澄清及具体原因仍待审核。baseline / 002 也未生成有效终态，因此不能据两组错误标签不同宣称答案质量变好。其余两道预期 clarify 和一道预期 refuse 的题，两组终态符合标签，但标签相符不等于全文正确。

已知输入 **79954**、已知输出 **24833 Token**。35 次输入型模型尝试明确标记输出不适用；其中一次 503 输入未知，其余已知输入均计入费用。无效响应和不完整生成的已知用量同样保留，没有因为结果失败漏计。

按冻结峰时、无缓存优惠口径，**已知用量估算小计为 0.2880645 元**。baseline 的用量完整估算为 0.130083 元，split-v1 因一次 503 用量未知，完整费用为 null；全批完整费用与供应商实际账单也保持未知。已知小计不是实际扣费，也不能断言它是实际账单的下界。

本批的零 429 是运行观测；其他共享流量无法由客户端完全控制，不能据一次运行承诺限流已永久消除。重试/调度修复影响的是两组共同的实验可靠性，不作为 split-v1 的质量收益。
