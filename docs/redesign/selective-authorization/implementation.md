# 按实际影响处理授权变更：实施与验证

日期：2026-10-25。状态：需求和方案已确认，本地实现与验证已完成，待人工验收。对应[规格](spec.md)和[技术方案](technical-plan.md)。

## 实现结果

- 取消注册表改为调用当前权限检查，只取消实际失权的任务。保留写者优先、重复取消保护和单 API 进程约束。
- 新增 `RunAuthorization`、`RunDependencies` 和 `TrackedCorpus`。候选范围始终固定，读取及依赖登记在同一段读保护内完成；同一运行的读取登记串行，避免并发保存把来源集合写小。
- 范围判断登记实际使用的知识库元数据；关键词读取登记参与计算的全部切片来源；向量排序登记参与比较的候选版本，而非只记 Top-20 或最终引用。
- 新增授权仅供新任务绑定。尚未使用即撤权的候选资料被后续读取排除；已有依赖失权则停止。账号改密、停用、注销及凭证自然到期也会停止相应任务。
- 历史仅选择最终带入的最近四轮，再继承其来源与历史标识。来源写入现有消息 `provenance` JSON，无数据库结构迁移。旧消息按已有来源保守复核。
- 进度与终态保存前复核；请求执行器先进入清理保护区再完成准入，防止首次调度前取消留下孤儿。模型请求落账之后、真正调用提供商之前再检查一次。
- 问答回执只检查当前身份。轮询遇到授权变化时在发送保护内重建当前可见的历史，失权内容被遮蔽；其他普通资料接口保留原发送前保护。
- 权限检查故障最多重试一次；仍失败则相关任务以 `error / authorization_check_failed` 结束。确认失权使用 `interrupted / authorization_changed`，不把数据库故障伪装成撤权或资料不足。

## 评测协议与兼容性

新冻结协议在 `EVAL_PROTOCOL` 增加 `authorization=frozen-input-permissions-v1`，manifest 保存 `subject_role` 和逐题 `scope_bindings`。原授权版本仍保留用于审计；实验输入身份独立比较，不受无关全局版本提升影响。

执行时恢复原始绑定，不因增权重新扩大输入。检查冻结资料的有效权限、知识快照、活动版本、元数据、原文和向量哈希；原有代码、提示、模型、运行环境、预算与调度状态检查继续生效。复核数据库故障、确认失权或输入变化均会停止后续批次调用。

旧实验目录仍受代码和协议身份检查保护，不改写旧 manifest、报告、答案、裁决或账本来续跑。新逻辑不能直接改变已经执行的旧进程，需要以新代码启动符合协议的运行。

## 已知边界

- 在线撤权协调仍仅支持单 API 进程。离线评测在检查点发现变化后停止，不提供跨进程即时强制取消。
- 检索算法实际读过的所有资料都可能影响排序，不能仅用最终引用判断影响。旧历史缺少精确读取记录时采用原有来源的保守上界。
- 元数据、引用和历史的公开仍受当前权限控制。已经发给浏览器或提供商的内容无法追回，正在执行的同步计算也无法仅靠协程取消强制终止。
- 本轮只完成本地实现与验证，不代表云端部署、真实模型验证或人工验收完成。
