| 部分 | 当前处理 |

| 实验漂移门禁 | 冻结当前主体、权限、快照、原文、模型名称和请求别名、CA 哈希、运行时依赖与预算；不接受来源变化后续跑 |

协议冻结用于证明给定输入的外部行为一致，不证明真实答案正确率或召回提高。旧源码仅存在于测试用隔离进程；新运行时不导入旧 Pipeline、Store 或 Go 服务。

## 实验准备与剩余门禁

已审核 `scope-40-v1` 转为新格式后为 40 题（dev 10、test 30），649 个分块、45 个必需证据组，默认范围 16 题、显式范围 24 题。审批来源得以保留，但不等于新引擎的执行费用已获批准。

提案仅比较 dev 的 baseline 与 split-v1，D 变体、seed 12，共 20 个输出；HTTP 调用上限提议 150，judge 0。不得沿用旧引擎预算审批。正式 test、补检索与回答检查均不包含在此次提案中。

现有 UTF-8 字节加最大输出是保守预留估算，不是匹配模型的 tokenizer。按题目不被改写增长的候选/上下文包络估算，4/10 道 dev 可能超过默认 48000；本批没有直接提高限额，也没有删证据来绕过限制。最大包络约 61851，但它不是改写后输入或实际费用的保证上界。

真实实验前仍须核对：已审语料和当前授权切片是否一致、网关别名对应的实际模型及价格、预算的可运行性和费用授权。人工盲审前正确率、错误拒答、无依据陈述、遗漏率均不生成有效性结论；回答检查尚未启用，误改率保持 null。

旧失败题只作回归。已审题中历史原文重叠和条件消歧限制仍保留在来源记录中，不把同一来源换个问法当作独立新收益。

## 服务器隔离边界

验收目录 `/opt/it-helpdesk-rag-rewrite-m3`，Compose 项目 `it-helpdesk-rag-rewrite-m3`，与原项目 `it-helpdesk-rag-cloud` 分离。原入口为服务器回环 `3000`，候选入口为回环 `3001`；没有公网开放候选端口，也没有切换原入口。

生产库只读 `pg_dump`，恢复到候选数据库；旧上传文件按版本 ID 显式映射并核对内容哈希后复制到新卷。迁移前后核对原有字段的数据指纹和行数，新增字段单独验收。备份、私有配置和业务验证产物只在服务器受限目录保存，不进 Git、镜像或普通源码包。

服务器无法从 Docker Hub 拉取基础镜像，验收临时使用已缓存的 Python 3.12 解释器运行时，移除其中 `/app` 的旧源码与虚拟环境；注入官方下载并校验 SHA256 的 Node。新应用使用独立虚拟环境，按 `uv.lock` 固定版本与工件哈希安装，仅临时替换下载前缀，镜像最终保留原锁文件。仓库 Dockerfile 默认仍使用独立的 Python/Node/nginx 基础镜像，不绑定旧业务镜像名称。

新版本预览关闭真实推理。完整问答、入库与浏览器链路通过服务器上的独立合成数据库和 HTTP 替身验收，不把模型替身结果当作真实模型联调或答案质量结果。

## 已审题集与服务器的来源差异

服务器已完成 40 题格式转换，保留原审批。本次副本并不是原审核时的同一命名空间：原评测主体不存在，原权限 revision=0，服务器副本 revision=16；7 个库、9 个版本及 649 个分块的 ID 均不同。因此真实实验尚未冻结或执行。

进一步按库名/组织、文档标题、文件名、来源、分块序号、原文、坐标和内容哈希匹配，649/649 分块都有唯一对应，0 缺失、0 歧义，版本和库也一一对应。私有映射审核包已存于服务器 `artifacts/experiment/mapping-review.json`，没有直接替换审批清单或伪造权限版本。

下一步应显式建立服务器的评测主体及范围，导出新快照并审核映射后的来源，再讨论价格和执行预算。不能仅因原文哈希相同就沿用旧主体/权限审批，也不能跳过冻结门禁直接生成答案。
