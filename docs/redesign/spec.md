# 全栈重实现需求规格

日期：2026-10-17。状态：全栈范围与 LangGraph 方向已确认；本规格细节与技术方案待人工确认。

## 1 目标和重实现边界

按从零选型设计可上线验证的企业知识问答系统。重新编写 Go 业务后端、Python RAG/Worker/评测执行、Vue 前端及两种语言的数据访问；新领域代码不导入旧 Pipeline、旧 Store、旧 handler 或旧前端组件。依赖现状清单确认用户行为，依赖契约确认兼容边界，不能通过包一层旧函数宣称完成重构。

技术栈采用 Go/Gin、Python/FastAPI/LangGraph、Vue 3/TypeScript、PostgreSQL/pgvector；保留文件卷和单机 Compose，支持 Windows 开发与 Linux 容器。LangGraph 是问答编排库，不要求 LangChain 模型封装、LangSmith 云服务或新的执行服务。

本轮包含当前已经交付的全部功能和最初要求的自适应检索/回答检查与评测闭环。旧第二阶段尚未实现的反馈、工单修复和业务看板继续作为独立待办；OCR、SSO、多实例分布式一致性、任意工具执行不自动加入本轮。云部署需在本地验证和用户验收后另行安排。

现有原文件、数据库、历史引用、私有评测题、原始答案及人工裁决是受保护资产；不能通过清空数据库或重新生成黄金答案完成“从零实现”。

## 3 有界自适应问答

### A1 逐任务覆盖

从原问题及已消解指代识别用户要求，最多两个独立任务；每个任务保留组织、时间、对象及必要条件。若更多要求不能安全归入两个任务，则澄清范围，不静默丢项。单任务仍建立一个任务，不能依赖评测黄金答案建立线上任务。

先检查最终上下文，再在必要且预算允许时诊断融合候选。输出每个任务的 covered/partial/missing/ambiguous/unknown、支持 chunk/version/字符区间、缺失要求和原因。完整支持的判断须结合前提、顺序和适用范围，不以文本相似度替代。模型判断可能出错，人工审查其假阳性和假阴性。

候选没有支持、候选已有但选择丢失、检查无法判定分别记录。找不到的证据 ID 为 []；引用位置存在不等于语义正确，程序校验和人工语义裁决分开。

### A2 最多一次条件补检索

仅在任务缺证据、组织条件明确、候选诊断允许且预算足够时触发。最多一轮、两个缺项查询；不能重查所有已覆盖任务，不能改变绑定知识库、授权文档集合、组织或快照。保留首轮候选，按同一融合、重排和上下文预算重新选择，随后复查覆盖。

候选已有支持但未选入上下文，记录 selection_loss；本轮不借补查隐式更换证据分配策略。去重、任务名额分配、扩大 Top-K 或更换检索模型另开实验。补查失败/仍缺时只回答有独立证据的部分或明确拒答，不再循环。

### A3 回答依据和完整性

启用回答检查时，先在服务端生成草稿，再独立检查关键陈述的引用语义支持，以及已支持的用户要求是否遗漏。检查输出陈述/任务/引用映射、缺项与不支持陈述；不能用单一总分作放行条件。

最多修正一次，并复核一次；修正只使用同一最终证据，不补检索、不加入模型常识。仍不通过不输出该草稿。证据确实不足时拒答；模型格式、超时、网络或检查不确定性是 error，不能伪装成正确拒答。

已有编号校验和比较对象引用校验仍保留为确定性检查。企业配置步骤、账号、地址与政策不能因“模型知道”而绕过知识库。

### A4 停止与预算

所有模型调用、重试、检索、等待和输出共享请求 deadline；所有 LLM/Embedding/Rerank 调用计入请求预算。规定补查次数、修正次数、HTTP 次数、累计 Token、输入/输出边界。达到上限后不得以自动重试绕过。

首版建议每请求最多 24 次模型 HTTP、总预留 48000 Token、110 秒总时限，作为开发配置待实测校准；模型级限时取剩余时限与单次上限较小值。Token 上限必须有模型匹配 tokenizer 或可验证保守估计，缺用量不能写零。图的递归上限只是最终防线，不能替代这些业务上限。

### A5 SSE 与体验

保留 POST SSE。B0/B1/B2 对照保留直接流式行为；B3 完整检查模式先发送进度、缓存草稿，验证通过才发送最终正文和引用。进度不算首字；检查后分段发送不能称为模型实时 Token 流。浏览器必须能停止请求，并明确完整回答、部分回答、澄清、资料不足与未验证错误。

## 4 效果与实验要求

| 编号 | 必须完成 | 约束 |
| --- | --- | --- |
| E1 查询拆解闭环 | 当前旧实现 baseline/split-v1 成对实验；再核对新实现的基线行为与输入协议 | 同模型、题目、语料、权限、Prompt、Top-5/8000 字符/40 融合候选；付费预算先确认 |
| E2 分阶段单变量 | 锁定基线 → 拆解 → 条件补查 → 回答检查 | 新框架迁移不与策略收益混算；B2/B3 可独立开关，不能一次全部开启再归因 |
| E3 指标与裁决 | 候选/融合/重排/上下文覆盖、答案正确、错误拒答、无依据、误改、调用、Token、P95 | 问答与评分分账；失败保留；小样本披露不确定性；人工盲审裁决 |
| E4 题集有效性 | 旧失败题作回归，新收益用独立冻结题 | 旧题改写不当新独立事实；scope-40 来源重叠如实披露；新评测标准先人工审核 |
| E5 修正风险 | 相同初始草稿对比修正结果，独立测端到端体验 | 原正确被改错数/人工正确初始草稿数，分母零记 null；评价模型不独自宣布有效 |

框架重实现可以先用替身与冻结协议验证，不必等待付费实验才写所有基础功能；但 **在旧拆解效果闭环和人工策略选择完成前，不默认上线补查和回答检查**。已有 150 次开发 HTTP 提案不自动授权新实验、重复运行或改造后的额外调用。

## 5 验收门禁

1. 需求与架构：确认本目录的功能、流程、边界、接口和分阶段计划。
2. 结构独立性：新代码在不加载旧源码目录的环境可构建运行；节点直接依赖新端口接口，不能委托旧 Pipeline。
3. 基础全栈：新 Go/Python/Vue 联通；所有当前已实现用户功能逐项走通；API/SSE/权限/版本契约兼容。
4. 数据正确性：空库和旧库副本升级；ID、内容哈希、文档版本、向量身份、历史引用与授权一致；备份可独立恢复。
5. 基线保真：固定替身比较模型输入、实际请求、证据、公开事件与终态；变更点必须事先列明，不能用最终答案相似掩盖差异。
6. 自适应控制：补查/修正次数、预算、超时、取消、故障、非法输出、候选选择损失、部分回答均有负例验证。
7. 效果验收：人工成对净收益、风险指标与实际成本；错误拒答、误改、延迟容忍值先看开发数据，再在正式测试前锁定。
8. 交付：各批验证后 commit，代码与测试人工验收；生产切换、推送和部署另行明确执行。

已有正确率 ≥85%、Recall@5 ≥82% 可作为质量目标；旧首字 2 秒/总时长 5 秒仍为历史优化目标，不能在增加草稿检查后未经测量承诺。权限负例必须全部通过，越权是阻止发布的条件，不能用总体正确率抵消。
