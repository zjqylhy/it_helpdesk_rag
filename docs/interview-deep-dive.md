## P0 必须掌握 核心设计与系统扩展

四十题。先讲清项目骨架与关键取舍，再准备规模、性能、质量及多实例演进；这些题决定面试官是否继续深入。

### 项目定位 架构与完整链路

#### R001 用 90 秒介绍项目

我做了一个面向 IT 操作资料的知识助手，作为 Go 后端向 AI 应用研发延伸的个人展示项目。它处理 VPN、Windows 故障排查等资料，支持文档导入、版本更新、多轮问答、来源引用和用户组权限。业务层使用 Go/Gin，RAG 和异步导入使用 Python/FastAPI，业务数据、切片和向量统一存 PostgreSQL/pgvector，前端是 Vue 3。

检索采用中文 BM25 与向量双路召回，经 RRF 融合和 Qwen 重排，再判断证据是否足够，最后用 DeepSeek 生成有引用的回答。工程重点是新版本全部完成才事务发布、请求绑定不可变快照、数据库约束防重复生成，以及撤权后停止后续流输出并遮蔽历史。效果方面，旧单库冻结测试的可回答题人工正确率为 144/160，多文档子集只有 22/30。我据此补了阶段归因和独立跨库成对评测工具，当前 40 题已冻结，真实拆解实验尚未运行。

#### R002 为什么做这个项目

直接动机是求职展示，并验证自己是否能把模型调用做成可维护的应用。IT 资料适合检验三个问题：口语问题能否定位准确步骤；不同学校、年份的规则会不会混用；更新或撤权后旧知识会不会继续输出。业务痛点是合理的场景假设，不能包装成已有企业客户访谈、真实工单下降或付费收入。

#### R003 项目解决了谁的什么问题

普通用户通过问题查步骤和依据；管理员负责上传、更新、停用、授权；开发者通过冻结题集定位链路失败。价值既包括回答，也包括“何时不能答、答案来自哪个版本、谁可以看到”。目前没有真实活跃用户量、工单替代率或节省人时的正式统计。

#### R013 整体架构如何划分

浏览器经 Web/Vite 或 Nginx 的 `/api` 访问 Go。Go 负责身份、文档生命周期、会话、授权和 SSE 持久化；Python 负责解析、向量化、检索、重排、证据判断、生成和评测。两者访问同一 PostgreSQL；Go 写原文件，Python 从共享文件卷只读解析。模型调用集中在服务端适配器。

#### R049 一次问答的完整链路

Go 验证身份、会话归属、范围及请求约束 → 绑定授权 revision → 保存 generating 消息 → 读取可用历史 → Python 绑定授权版本与知识快照 → 改写或范围理解 → 双路召回、融合、重排 → 选择上下文 → 判断证据是否足够 → 拒答、澄清或流式生成 → 校验引用 → Go 保存终态及引用。

典型首次已选单库的成功路径有四次模型 HTTP：Embedding、Rerank、充分性判断、流生成；多库通常再有一次范围理解，多轮单库通常增加改写。提前澄清、空证据、重试及实验拆解会改变次数，所以一次用户请求不能按一次模型调用估算成本。

#### R027 从上传到可检索的链路

管理员上传 → 校验类型、大小和知识库 → 随机路径保存原文件并计算 SHA256 → 事务创建文档版本和任务 → 返回 202 → Worker 领取、解析、切片、Embedding → 校验租约 → 事务写切片、切换有效版本并生成知识快照 → 新请求使用新快照。模型网络调用在发布事务之外完成。

#### R009 最值得讲的三个难点

第一是知识更新一致性：避免新旧切片混用和失败版本覆盖；第二是动态权限：检索、历史、下载及流输出都必须受控；第三是效果归因：把没召回、重排丢失和答案漏写区分开。每个难点都有明确机制及反例，适合连续追问。

#### R007 这个项目和常见 RAG Demo 的差别

可重点展示五项：任务租约及失败保旧；不可变知识快照和引用快照；检索前授权与在途撤权；按原文证据组计算召回；保留失败、共享预算、随机盲审的成对实验。区别应通过代码和验证材料说明，不能靠“企业级”“高并发”等形容词替代证据。

### 主体组件与检索选型

#### R014 为什么 Go 和 Python 两种语言

Go 承担熟悉的业务服务、HTTP 流转和数据库约束；Python 使用解析、中文分词、RAG 评测生态。代价是两个运行时、内部协议和部署排障成本。规模更小的项目完全可以全 Python；本项目的分层理由是职责和生态，不是断言 Python 不能做高并发。

#### R016 为什么 PostgreSQL 加 pgvector

可以在一个事务中协调版本、切片、有效指针和快照，并在向量查询里限制版本集合，减少跨存储同步成本。当前只有数百切片，精确检索容易建立可靠基线。pgvector 官方支持精确和近似检索；项目实际使用的是精确余弦距离排序。[官方说明](https://github.com/pgvector/pgvector)

#### R017 为什么没选 Milvus 或独立向量库

当前数据量不足以抵消新增集群、元数据同步和授权过滤的复杂度。未来在向量规模、吞吐、索引维护或多租户隔离成为瓶颈时，再用同语料对比召回、尾延迟和运维成本。选独立库时必须设计业务版本与索引发布的可见性协议。

#### R018 为什么没用 Elasticsearch

中文 BM25 先用 jieba 和 rank_bm25 建轻量内存基线，避免额外服务。代价是语料加载、分词和打分消耗进程内存及 CPU，多实例要各自重建。大规模及复杂过滤时可考虑 Elasticsearch/OpenSearch，但不能把“没有倒排服务”描述成同等生产能力。

#### R019 为什么没用 Redis 或 Kafka

低吞吐导入任务直接保存在 PostgreSQL，用事务领取与租约恢复；请求互斥依赖唯一索引。这样避免数据库和消息系统的双写问题。若导入吞吐、跨服务消费、回放需求扩大，可引入队列和 outbox，仍需消费者幂等；消息中间件不会自动带来 exactly-once。

#### R020 为什么不用完整 LangChain 或 LlamaIndex

主链路显式编排，便于控制快照、权限、调用预算及失败状态，减少框架内部隐式重试或上下文变换。代价是协议适配、评测和异常处理要自己维护。Ragas 的可选适配使用 langchain-openai，并不代表在线主链路采用 LangChain。

#### R021 Qwen 和 DeepSeek 各负责什么

Qwen 提供 Embedding 与 Rerank，DeepSeek 负责范围理解、改写、充分性判断及答案生成。默认配置保留历史模型名；网关可将 chat 别名映射到不同实际模型。讲历史成绩必须绑定原运行清单，不能将旧 Pro 单库结果算作后来 Flash 跨库结果。

#### R022 为什么三个模型能力分开

Embedding 是双编码器式语义表示，便于离线预计算；重排对问题与候选联合判断，适合少量候选的精排；生成模型组织自然语言答案。分开后可独立测量和替换，也多了延迟、接口和费用。当前没有完成厂商间效果排名，不应说某厂商一定最佳。

#### R025 目前最大的架构取舍是什么

优先减少组件数量，用 PostgreSQL 承担业务与任务，以单实例内存索引和授权锁控制复杂度。收益是容易复现和验证；代价是扩容、可用性和资源隔离能力有限。这是明确的演示与开发阶段取舍。

#### R024 为什么 Docker Compose 而不是 Kubernetes

当前设计为单 Go、单 RAG、单数据库和 Web，Compose 可以复现部署与持久化。Kubernetes 不会自动解决会话取消、快照缓存、共享文件和数据库迁移等应用问题。扩容前要先消除进程内权威状态，再考虑编排平台。

#### R052 BM25 和向量怎样互补

BM25 容易抓住原文精确词，向量能匹配语义相近的口语表达；两者也会共同漏掉组合问题的一部分。应比较各路独有命中和证据组覆盖，不能只展示最终均值。项目旧测试中，单纯融合的正确率未必高于向量，重排才带来主要实测提升。

#### R057 RRF 的公式是什么

对于候选 d，将它在每条召回列表中的排名贡献相加：score(d)=Σ 1/(60+rank_i(d))，排名从 1 开始；不在某路则该路贡献为零。实现按总分降序、id 升序稳定排序，不混加 BM25 原始分数和余弦相似度。

#### R061 重排做了什么，为什么有效

把问题与少量候选交给重排接口重新比较相关性，弥补初召排序较粗的问题。它只能重排候选池里已有内容，找不回没召回的证据，也未必优化“多个事实同时覆盖”。当前单库送正文，跨库另外加库名、组织和文档标题。

### 核心正确性与效果设计

#### R034 切片策略是什么

默认每个原文段落独立切分，长度 700 字符、重叠 120，步长 580；短段落直接保留，不跨段合并。切片保留页码、段落、章节、start/end 字符区间及内容哈希。它不是 token 切片、语义切片或父子块算法，代码里也没有按句子智能吸附边界。

#### R044 发布事务里具体写什么

先锁任务确认租约，再锁知识库行；写该版本的切片和向量、完成版本元数据、条件更新 active_version、递增 revision、插入启用文档的版本列表快照，并将任务标 completed。事务失败整体回滚，旧有效版本保留。

#### R075 跨库快照怎样确定身份

单条 SQL 读取允许库的最新成员快照，按 kb_id 排序，把成员库 ID、快照 ID、名称、组织等生成确定性组合哈希。授权过滤还改变版本集合及成员身份。在线每轮可绑定当时最新快照；正式离线评测则另外冻结成员，二者不能混淆。

#### R087 为什么重排后还要充分性判断

相关内容不一定含完整答案，也可能缺组织、步骤或前置条件。结构化判断返回 answer、refuse 或 clarify 及证据编号，形成生成前的门。它本身也是模型判断，会产生误拒答或误放行，需要单独用开发集及行为指标评估。

#### R117 为什么必须检索前授权

如果先全库检索或重排再过滤，受限正文和组织元数据已经进入模型。AuthorizedStore 在成员快照、corpus、vector_search 前收敛可读版本，BM25 也只索引这个集合。只隐藏最终引用或前端按钮无法阻止模型侧泄漏。

#### R120 撤权与发送并发怎样处理

单 Go 进程使用 policy.RWMutex：发送片段持读锁，授权修改持写锁，事务提交后取消登记的在途 context。等待模型时不长期持读锁，避免整个生成阻塞撤权。保证边界是撤权生效后不再经该进程继续放行旧版本流片段，不是撤回用户已看过的数据。

#### R130 90% 到底是什么

旧 qa-v2 单库冻结 200 题中，有 160 道可回答题；D 的人工正确为 144，正式答案正确率是 144/160=90%。另有 25 拒答和 15 澄清，行为结果分别是 25/25、13/15。不能说“180/200”“200 题回答准确率 90%”或“跨库正确率 90%”。

#### R068 多文档题为什么仍然差

旧 Windows 子集中，八道失败的互斥主因是召回 5、重排选择 2、答案组合 1；实际重排损失涉及四题，其中两题也有召回缺失。全部八题五段正文合计仅 802–1743 字符，没有证据说明失败由 8000 字符裁剪造成。应按最早证据损失和次因解释，不能把多因计数相加当题数。

#### R151 如何逐阶段归因

依次检查原文锚点是否在授权范围、BM25/向量候选并集、融合 Top-20/40、重排名次、最终上下文及答案事实。最早缺失作为主因，后续损失可列次因。历史没有保存完整排序时应标缺失，不能从最终答案反推精确重排分数。

### 系统扩展 容量与演进

#### R194 突然有一千个用户同时提问

当前无法直接承诺承载。先按到达率和平均服务时间估算在途量，再测队列等待、连接、CPU、外部限流及尾延迟；增加有界排队和拒绝，避免无限堆积。Semaphore 只限制部分模型调用，不等于接入层过载保护，也不是每秒速率限制。

#### R195 如果扩到一百万文档怎么改

先估切片、向量、原文和索引规模，而非只说文档数；引入对象存储、批量导入、分区或独立检索服务，离线构建并发布索引。业务版本与授权过滤仍要贯通；ANN、关键词服务、元数据的发布一致性及撤权时效必须分别验证。这是扩展设计。

#### R125 多实例权限保证是否成立

数据库 revision 可跨实例检测，但 policy 锁和 flights 取消表是本地的，不能提供多 Go 实例同样的瞬时协调；另有全局 generating 启动恢复问题。当前应明确单实例约束。扩展需设计共享撤权通知、实例持有者和最终发送边界，不能仅加 Redis pub/sub 就声称严格一致。

#### R188 当前最需要补哪些生产能力

先补容量基线、超时与连接复用、全局限流、模型真实身份追踪、状态持久化确认和监控；再处理多实例任务/会话归属、共享文件改对象存储、权限协调、索引分发及迁移。当前没有 Prometheus/Grafana 全套、完整 tracing、企业 SSO 或 K8s，不能将其他个人项目能力移植到本项目叙述。

#### R196 如果要求回答更快怎样排优先级

先拆范围理解、Embedding、SQL、BM25、重排、判定、首字及代理耗时，再优化占比最大的环节。可测客户端复用、有界库并行、跳过不必要的理解调用和缓存安全的计算结果。不能在无对照下删除充分性判断或更换模型后同时声称质量不变。

#### R197 如果要求正确率从 90% 到 95%

先确认同一任务分母及验收集，按阶段和场景归因，在开发集选择一个变量，再用未见集成对评估质量、误拒答、成本与延迟。不能通过删困难题、放宽必要事实或不断重试挑答案达标；新跨库还需要先建立自己的真实基线。

#### R072 Embedding 模型更换怎样迁移

现有 corpus 校验模型标识与维度，不兼容则拒绝并要求重导。更稳健的扩展是按真实模型版本建立新向量集合，后台重算、同题对照、原子切换并保留回滚。网关别名相同但底层模型改变也可能破坏兼容性，别名本身不足以证明向量一致。

#### R098 有没有答案缓存和幻觉兜底

首期没有答案缓存，减少知识与权限变化后复用旧答案的风险；也没有失败后切模型、联网补资料等自动兜底。若未来缓存，键需覆盖主体授权、知识快照、模型和 Prompt，并明确撤权失效。拒答与引用检查降低风险，但不是零幻觉保证。

#### R182 备份恢复为什么要同时包含文件

数据库保存原文件路径和哈希，单独恢复 SQL 会留下缺失来源。维护窗口内尽量暂停写入，备份数据库和文件，恢复后逐表及逐文件校验，再验证引用、权限、上传及问答。当前有本地 Docker 恢复记录，不能推导已有跨地域灾备、PITR 或承诺的 RPO/RTO。

#### R183 schema 迁移有哪些风险

当前 Go 启动执行增量 SQL，包括历史权限迁移；简单部署方便，但多实例并发迁移、长表锁及失败回滚需要额外设计。未来可用独立版本化迁移流程，采用先扩展、兼容读写、回填、再收缩，避免应用启动承担任意生产变更。

## P1 高频深挖 关键机制与工程难点

九十题。围绕 P0 的设计理由展开实现、约束和验证。Go 后端岗位优先会话、权限、事务及故障窗口；AI 应用岗位优先检索、跨库、评测及模型适配。

### 导入任务 版本与一致性

#### R028 为什么异步导入

文件解析和 Embedding 时长受文档与外部 API 影响，放在上传请求中会占用连接且难恢复。202 只代表任务已接纳，前端需轮询进度并展示完成或失败。当前界面按四秒间隔轮询管理数据，不是 WebSocket 实时任务推送。

#### R032 文档解析支持到什么程度

PDF 使用 pypdf 提取文本并保留页码；DOCX 使用 python-docx 读取段落及标题样式；Markdown/TXT 用 UTF-8 读取并保留段落、章节。扫描 PDF、OCR、复杂表格、图片内容、PPT 和完整 DOCX 表格解析不在当前能力内。不能把导入成功等同于版面语义完整保留。

#### R035 为什么保留字符区间和原文锚点

检索结果需要定位来源，评测还要在切片参数改变后重新映射证据。仅保存 chunk ID 会让重切片导致黄金标签失效；页码相同又太宽松。版本、段落和字符区间让相邻重叠切片能合并判断是否完整覆盖所需原文。

#### R036 700 和 120 是怎么选的

它们是配置中的初始值，没有完成独立切片参数消融，不能称为最优。小块定位精确但容易拆散步骤，大块完整但会稀释主题并增加成本；重叠缓解边界丢失，却占用存储和 Top-K。调参应在开发集同时看证据组覆盖、正确率、费用和重复片段比例。

#### R038 Embedding 如何分批及对齐

每批最多 20 段，按返回的 text_index 或 index 重建顺序，检查索引类型、范围、重复、数量、维度、有限数值及非零向量。不能假设提供商总按输入顺序返回；错误向量不能静默补零后发布。

#### R039 查询和文档向量是否完全同处理

两者必须属于同一兼容向量空间。直连适配器区分 document 与 query 的 text_type；网关按其 embeddings 协议传入模型别名和显式维度，不能假定支持所有厂商特有参数。模型、维度和预处理变化需要兼容性验证，维度相同也不代表语义空间相同。

#### R040 为什么把 Embedding 放在事务之外

外部调用可能数十秒，持有数据库事务会长时间占用连接与锁。当前先解析及向量化，再用短事务发布，失败时旧有效版本仍可用。代价是中途失败重试可能重新计算整份向量，项目没有分批落盘的完整断点续传。

#### R041 Worker 怎样领取任务

单条 UPDATE 内选择 queued 或租约过期的 processing 任务，使用 `FOR UPDATE SKIP LOCKED`，写入 owner、attempts 和 90 秒租约。SKIP LOCKED 允许竞争者跳过已锁行，适合队列领取；不应拿它做需要一致完整结果的普通业务查询。[PostgreSQL SELECT 文档](https://www.postgresql.org/docs/current/sql-select.html)

#### R042 心跳和重试的具体规则

处理期间每 20 秒续租至 90 秒。租约过期可重新领取，恢复领取次数要求 attempts 小于 3；耗尽后明确 failed。普通处理异常直接 failed，不是所有错误自动整任务重试；管理员重试接口只允许 failed，重置 attempts 等状态重新排队。

#### R043 租约过期后旧 Worker 还在运行怎么办

心跳及状态更新携带 owner，发布前再对任务行加锁并核对 owner、processing 及租约有效期。失去所有权的旧执行者不能发布。它控制数据库发布，不保证取消已经发送的外部 Embedding 请求或避免其费用；当前主要按单 Worker 运行，不能声称已完成任意多实例故障证明。

#### R045 两个文档同时发布会不会丢快照成员

同库发布与启停都锁知识库行，串行构造该库当前有效版本集合，避免两次发布各自覆盖成员。不同库可以独立发布。跨库读取用一条 SQL 绑定成员的读取视图，不等于所有库拥有相同 revision 或执行全局分布式事务。

#### R047 文档停用和权限撤销有何不同

停用改变之后请求可见的知识快照，旧回答仍引用旧版本；权限撤销改变当前用户能否读取来源，历史也要重新鉴权。停用不会自动清除旧回答，也不等于追溯性保密删除；已经绑定旧快照的在途请求与之后的新请求应区分。

### 召回 融合 重排与上下文

#### R050 BM25 的基本原理

BM25 结合词在文档中的频率、词的区分度和文档长度归一化，词频贡献随出现次数逐渐饱和。它擅长型号、命令、错误码及专名等精确词匹配，对同义表达较弱。当前使用 rank_bm25 的 BM25Okapi，输入是预先分词的列表，库本身不替项目完成中文预处理。[项目说明](https://github.com/dorianbrown/rank_bm25)

常见形式为对查询词求和：IDF(t) × tf(t,d) × (k1+1) / [tf(t,d)+k1×(1-b+b×|d|/avgdl)]。k1 控制词频饱和，b 控制长度归一化；具体 IDF 平滑要以库实现为准。加大词频不会无限线性增分，长文档也不能仅靠重复关键词天然占优。

#### R053 向量检索使用什么距离

SQL 使用 `embedding <=> query_vector`，按余弦距离升序并用 id 打破并列。余弦距离为 1 减余弦相似度，通常范围为 0 到 2，不是正确概率。当前 schema 没有 HNSW 或 IVFFlat 索引，不能把 pgvector 的可选能力说成项目已使用。

#### R054 为什么先用精确检索

当前数据量小，精确检索有利于排除近似索引带来的召回损失，作为 ANN 对照。规模扩大后成本随候选数量和维度增加，需要看过滤选择率及执行计划，不能凭小库延迟推算百万向量性能。

#### R055 HNSW 和 IVFFlat 怎么回答

这是扩展设计：HNSW 以多层邻近图搜索，通常有较好的查询效果与速度，但建图和内存开销较大；IVFFlat 先聚类再搜索部分列表，需要权衡 lists、probes 和训练数据。引入后需在真实授权过滤下测 Recall、P95、内存和构建时间，不能只用无过滤的玩具集比较。

#### R058 为什么 RRF 不直接加原始分

两路量纲、分布和取值范围不同，直接相加会让某一路支配排序。RRF 使用名次统一尺度，但会丢掉原始分数间隔，且不能天然校准“是否相关”。k=60 是固定配置选择，没有完成本项目 k 值独立消融。

#### R059 单库 A B C D 四组具体是什么

A 是 BM25 候选后取五段；B 是向量候选后取五段；C 是两路各 Top-20 经 RRF 保留 20 再取五段；D 是同样的融合候选送重排，返回五段。当前多库在线入口只支持 D，不能把旧四组实验说成新跨库四组消融。

#### R060 RRF 为什么可能不如单路

候选池扩大也加入噪声，多路高排但不含必要事实的段落可能占据 Top-K。RRF 只看排名，不知道题目需要哪些事实；组合题尤其容易偏向一个子任务。不能因采用混合检索就承诺每题不退步。

#### R062 重排分数能当置信度吗

不能。当前分数用于同请求排序，未进行跨问题标定。项目以独立的结构化证据充分性判断选择回答、拒答或澄清。若想设阈值，需开发集标定、分场景验证并评估误拒答，不能直接取 0.5 当正确概率。

#### R064 Top-5 和 8000 字符是如何执行的

最多选择五段，正文总字符受 context_budget=8000 限制。单库遇到预算不足停止后续选择；多库跳过超预算项后继续尝试较短段落。标题、组织、JSON 包装及指令不计入该正文预算，因此不能说总 Prompt 最多 8000 字符。

#### R065 当前去重做到了哪一层

RRF 以 chunk ID 合并同一候选；当前没有上线按文本或语义的最终证据去重。trace 会记录正文完全相同的不同 ID，便于诊断，但“记录重复”不是“自动移除重复”。不同定位或权限来源也不能只凭相同正文随意合并。

#### R066 父子块、MMR、相邻扩展能否优化

可作为后续独立实验：父子块用细粒度检索加较大上下文，MMR 在相关性和冗余间权衡，相邻扩展补齐被切断步骤。它们会改变证据分布、预算和出处映射，需要分别对照。项目当前未实现这些策略。

#### R070 候选池外缺证据时怎么办

先查解析、分词、改写、范围路由和各路 Top-20，确认缺失从哪步开始；随后只在开发集尝试拆解、别名词典、召回数量或切片改进。增加重排模型能力无法直接解决候选池外缺失。

### 跨库 多轮与回答约束

#### R073 默认查询哪些知识库

空 kb_ids 表示默认业务库，即 default_search=true 且对当前主体有可读资料的成员；显式选择可以包含被排除出默认范围的验证库。指定 ID 去重排序、最多 32 个，非法或不可访问请求不能悄悄退回全部库。

#### R074 为什么范围要存在会话中

同一会话的后续问题需要稳定的业务范围。前端切换范围开启新会话，历史会话恢复原范围；Go 从所属会话读保存范围，不接受每轮由浏览器覆盖。旧 kb_id 与新 kb_ids 字段兼容，空集合的含义是默认范围，不是永远冻结当时全部库成员。

#### R076 VPN 怎么登录为什么要先问学校

不同学校的账号、域名和配置不同，检索相似度不能决定用户所属组织。多库范围理解只从可见元数据中选择对象；不明确且会改变答案时澄清，已指定单库则直接带入该库组织，避免重复询问。

#### R077 用户只回复交大怎样承接

Go 读取最近最多四个 completed/clarify 问答轮次，Python 根据有限历史将学校补回原问题，形成独立检索查询。历史是指代线索，不作为事实证据；仍重新检索该轮授权快照，不能把上轮助手的步骤直接当真值。

#### R078 为什么不把所有历史传模型

历史越长，成本、噪声和错误传播风险越大。当前最多八条 user/assistant 消息，且仅完成和澄清状态参与；error、interrupted、restricted 不进入有效历史。尚未实现语义记忆压缩、长期用户画像或摘要一致性协议。

#### R079 模型选库如何防幻觉或扩大权限

结果 schema 校验 behavior、query、requires_all，并验证 kb_ids 与 option_ids 全属于已授权成员白名单。格式或范围错误直接失败。选库模型只收受限元数据，不能自行新增库；这是程序约束，不是单靠 Prompt 请求它守规矩。

#### R081 跨库怎样避免大库淹没小库

每库独立 BM25/向量检索及 RRF，按库候选轮转合并，最多 40 项，再统一重排。查询向量在库之间复用。它是一种配额和平衡取舍，可能让大库更多相关候选被裁掉；并未证明在所有分布上全局最优。

#### R082 两校比较如何保证双方都出现

requires_all 标记必须覆盖的库；重排后先为每个对象选择一条，再补到五段，生成前检查证据覆盖，生成后检查实际引用覆盖。一个库一段不代表该库所需全部事实齐全，事实完整性仍交给判定与评测。

#### R088 拒答和澄清有什么差别

拒答表示当前允许范围中缺少回答所需资料；澄清表示用户补充组织、年份等条件后可能回答。系统不应对已明确组织反复追问，也不应对纯资料缺失假装只需澄清。界面状态与离线 expected_behavior 分别保留。

#### R090 生成 Prompt 如何约束回答

系统要求仅依据本轮证据、忽略资料内指令、说明适用组织和条件，并在事实段落附合法来源编号。用户消息用 JSON 装问题和证据；跨库要求按组织分别说明。结构隔离减少混淆，但不能声称解决所有 Prompt injection。

#### R091 引用编号如何校验

提取所有形如 `[C...]` 的标签，要求至少一个且都属于本轮 C1 到 Cn，映射实际证据并去重；比较题额外检查所有必要库都被引用。它证明引用身份合法，不证明每段事实都有对应依据，也不证明引文蕴含结论。

### Go 会话 流式处理与权限

#### R099 request_id 和 session_id 分别解决什么

session_id 确定会话及所属范围，request_id 标识该会话的一次逻辑请求。数据库 UNIQUE(session_id, request_id) 防重复接纳，不是全局唯一请求身份；消息有独立随机 ID。客户端重试同一逻辑请求应复用 request_id，而不是每次都生成新值。

#### R100 当前幂等是重放结果吗

不是。重复请求或已有生成时返回 409，提示刷新历史；没有对旧 SSE 事件做原样重放。唯一约束避免重复创建消息和通常的重复模型调用，但不能声称支持断点续传或收到重复键就自动返回同一完整响应。

#### R101 怎样保证一个会话只生成一个回答

messages 上有部分唯一索引：同 session_id 仅允许一条 status=generating。并发插入由数据库裁决，优于仅在进程内检查“有没有正在生成”。所有插入异常目前统一映射 409，数据库故障与业务冲突的错误分类仍可细化。

#### R102 为什么 POST SSE 而不是 EventSource

请求要携带问题 JSON 和 Authorization，前端使用 fetch 读取 Response.body。SSE 是服务端到客户端的文本事件格式，原生 EventSource 常见接口基于 URL 建连接；本项目没有为它另建 GET 事件订阅。消息分 event/data 和空行边界。[SSE 格式说明](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)

#### R103 SSE 与 WebSocket 怎么选

回答以单向增量推送为主，POST 流响应足够；WebSocket 适合持续双向交互，但增加连接、会话和协议治理成本。停止生成通过 AbortController 取消 HTTP 请求，暂不需要为一个停止动作维护双向长连接。

#### R105 客户端断开后如何保证消息状态保存

上游请求绑定浏览器请求 context，断开可传播取消；Go defer 用独立的 Background 加五秒超时保存当前答案和终态，避免使用已取消的 context 写失败。这个写库仍可能失败，代码会记录消息 ID；并非“只要 defer 就必然持久化”。

#### R106 进程崩溃时 generating 怎么办

Go 启动时把数据库全部 generating 改为 interrupted，让旧会话不永久锁住。这依赖当前单 Go 实例假设；多实例部署时，一个实例启动可能误伤另一个实例的活任务，必须改为带 owner、租约或实例状态的恢复机制。

#### R109 多层超时有哪些

Go 问答 context 120 秒、HTTP Server WriteTimeout 120 秒、内部 HTTP client 10 分钟、Python 模型请求默认 120 秒、Nginx proxy_read_timeout 600 秒。实际链路受较短边界控制，不能把 600 秒说成端到端可运行十分钟；同为 120 秒也需避免收尾没有余量。

#### R111 SSE 到浏览器的 done 代表数据库已提交吗

当前 Go 转发终态后在 defer 保存消息，存在客户端先看到 done、数据库写失败的窗口。成功流响应与持久化完成不是同一事务。若产品要求严格确认，可先可靠写终态再发最终确认，并处理断线查询；当前未实现这一强保证。

#### R113 登录与会话鉴权怎么做

密码用 bcrypt 验证；登录产生随机不透明 Bearer token，数据库只存 token 哈希及十二小时过期时间。每次请求关联 users 并检查 disabled；退出删除 token。不是 JWT，也没有企业 SSO、刷新令牌体系或完整登录风控。

#### R115 文档权限模型是什么

管理员全读，普通用户可读 all_users 文档或其用户组获授的文档，多个组取并集。权限在逻辑文档上，影响该文档版本的访问。新文档默认 groups 且无授权时普通用户不可读，旧资料升级一次性显式保留全员可读。

#### R119 授权 revision 的作用是什么

权限修改、全局 revision 增加和审计同一事务提交。请求记住 revision，Python 存储读取及 Go 每次流发送时检查，一旦不一致则失败或中止。全局版本简单保守，任一权限变化可能取消所有在途请求，牺牲可用性换取易验证边界。

#### R121 已发送给模型的证据能撤回吗

不能。HTTP 取消不保证提供商停止计算或删除已收到内容；存储检查与后续模型调用之间也不是跨系统原子事务。当前不能声称撤权瞬间所有外部动作都停止。需要结合最小上下文、可信提供商、数据保留策略和明确产品语义解释边界。

#### R122 历史回答撤权后怎么处理

读取历史时重新检查来源依赖，失权则 answer 变为隐藏提示，status=restricted，清空 citations、trace、snapshot 和 provenance 返回值。前端不能再拿旧引用下载原文。服务器数据库仍保留记录，并非已经物理删除；已经缓存到浏览器的内容也不能追溯收回。

#### R128 Prompt injection 的威胁模型

问题、历史、文档正文及名称都可能夹带指令。模型提示声明它们是不可信数据，程序再限制选库、证据标签及外部调用路径。当前没有工具执行能力，减少命令执行面；但仍可能被诱导错误回答，必须用攻击样本评估，不能宣称 Prompt 已实现安全隔离。

### 评测可信度与优化闭环

#### R010 哪些数字可以放进简历

旧单库数据：9 份真实文档、7 库、649 切片；200 题测试集含 160 回答、25 拒答、15 澄清；D 方案人工回答正确率 144/160，拒答 25/25、澄清 13/15，多文档 22/30。新跨库有 40 题冻结及六项权限协议，但没有真实优化成绩。Docker 环境另有部署验证文档，合计 8 库、10 文档、721 切片，不能和原生评测规模混算。

#### R131 四组效果分别是多少

共享改写的检索 Recall@5：A 78.65%、B 81.04%、C 81.35%、D 94.48%。端到端辅助答案正确率：A 66.25%、B 73.75%、C 72.50%、D 90.00%；只有 D 完成相应人工正式裁决。检索实验共享改写，端到端独立重放，两种运行的检索值不能任意混用。

#### R133 Recall@5 的实现定义是什么

每题有多个必须覆盖的 evidence_groups，组内来源可替代，组间必须组合。前五段覆盖某组任一锚点就记该组命中；题内召回是命中组数除以总组数，再对可回答题取平均。它是宏平均证据组召回，不是命中题数除以全部 200。

#### R135 跨切片证据怎么计分

按照相同版本和定位，将多个切片的字符区间排序合并，只有完整覆盖黄金原文区间才算命中。相邻且连续的片段可以共同覆盖，重叠不重复得分；只命中同页、同标题或几个关键词不算完整证据。

#### R136 为什么黄金集不能只让模型生成

模型生成的参考答案可能遗漏条件、引用错位或与被测模型共享偏差。当前流程是候选生成、人工编辑必要事实和来源、审核、冻结发布。题目来源审核只是标准有效，不代表未来生成答案已被人工判正确。

#### R137 怎样避免开发测试泄漏

按事实主题隔离，而不只随机分问句，避免同一事实改写跨 dev/test。看过正式失败后针对它调策略，该集就成为回归而非新盲测。旧 200 题只有 140 个事实主题，多文档题集中在 Windows，泛化能力必须按这个范围解释。

#### R140 为什么冻结语料而不只冻结问题

文档版本、组织元数据、默认范围和授权都能改变答案。冻结发布绑定题目、语料、成员快照、主体及组、授权版本集合和哈希；执行还检查当前授权。否则同一题集在不同时间运行实际上不是同一实验。

#### R141 冻结和当前授权冲突时谁优先

当前授权优先。FrozenScopeStore 校验主体、组、revision、成员及正文，失配就停止，不为了复现旧报告绕过撤权。知识冻结用于实验身份，不能成为永久访问证书；评测最好在独立数据库副本中执行。

#### R142 自动判分如何进行

按参考答案、必要事实、禁止错误及行为要求让 judge 辅助判断，保留逐项理由及复核标记。它可能受相同模型偏差、措辞和顺序影响，需要人工校准。当前正式答案正确率要求相应可回答题全部具备人工裁决，否则为 null。

现场读代码还应指出：judge 返回 citation_support，但当前 correct 的布尔表达式只合并必要事实通过、无错误和行为理由有效，没有单独把 citation_support 纳入门槛。这个字段存在不等于已形成硬门禁；不能把辅助分数描述为独立严格的逐引用语义验收。

#### R143 Ragas 在项目中做什么

可选地评估回答对上下文的忠实度，不是在线链路必需组件。Ragas 会增加模型调用，评分失败单列，不能补成零成本或直接当答案错误。旧报告忠实度与人工正确率不同，模型 judge 也不是客观真理。

#### R145 故障 未执行和缺失值怎样报告

故障保留为错误，不能从答案质量分母删除；未执行题为 pending，报告执行数与总数，不能宣称评测完成。缺失用量、未裁决正式结果使用 null，不补成 0。旧报告在 pending 存在时会将主要完整质量指标置空，具体指标分母需看实现。

#### R146 续跑如何保证可比较

旧单库要求数据、语料、commit、模型、路由、Prompt、预算配置等清单一致；新 scope 还绑定主体与范围及实验配置。旧 runner 允许重试 error 并保留追加记录，新 scope 保留已有终态、故障恢复另开运行；不能说所有历史入口都具有相同重跑策略。

#### R147 延迟成绩能不能直接引用

历史离线 total_ms 的边界、是否包含评分及不同运行汇总方式必须先核对，不能直接称为浏览器 P95 或线上 SLA。服务端首字、浏览器首字、完整答案和判分耗时分别统计；新 scope 明确问答计时在评分前结束。当前没有生产级压力下的端到端延迟承诺。

#### R150 如何讲一个真实失败案例

例如 windows-test-040：必要操作路径和省电选项都在上下文，模型只写取消选项，遗漏设备管理器、属性、电源管理路径，人工判错。说明“检索命中”不等于“答案完整”。同时该题标准比问句更严格，后续需让问题和必要事实对应，而不能事后改标准抬成绩。

#### R154 为什么先做查询拆解

八道失败中五道主要在候选召回，单改 Top-5 分配无法找回池外证据。先提出拆解实验符合已观察主因；重复文本和重排问题可另开实验。选择的依据是诊断，而不是“Agent 化更先进”。

#### R155 split-v1 具体怎样限制

只对规则识别为复合的查询尝试一次结构化拆解，输出空数组或两个不同的原问题连续片段，每段最多 2000 字符，不能等于整个原问题。保留原查询，子查询携带完整原问题条件且不能扩库。格式或协议错误回退原查询并记录失败。

#### R157 两组固定哪些变量

baseline 与 split-v1 使用同一冻结范围、授权、模型路由、充分性和生成提示，Top-5、8000 正文字符及融合候选 40 保持一致。候选内容因多查询而改变是实验变量的必要结果；不能同时扩大 Top-K、换模型后把全部收益归因拆解。

#### R160 盲审如何实现

同题两答案随机左右展示，隐藏策略名，提供同一问题、来源与标准；映射单独保存。先人工裁决再揭示策略，汇总改善、退步、均通过、均失败。盲审降低偏好，不自动消除标准模糊、题目相关和单审核者偏差。

### 模型适配 失败与资源控制

#### R026 服务之间信任什么

Python 只接受内部令牌保护的请求；主体由 Go 鉴权后传入，Python 再查询授权版本。浏览器提交的库 ID 只是范围请求，不能当作授权事实。内部令牌使用常量时间比较，但没有 mTLS 或零信任服务网格，网络隔离仍是部署假设。

#### R165 为什么把模型请求集中到适配器

统一处理路由、鉴权、超时、结构化输出、向量对齐、流终态、用量和预算，避免业务各处自行拼协议。接口保留 embed、rerank、json、stream，便于本地替身测试。模型返回 JSON 只代表可解析，还要逐任务校验语义字段和范围。

#### R167 网关失败会自动直连吗

不会。已经启用网关的能力失败就报错，避免绕过统一治理、变更数据目的地或混淆实验条件。直连与网关分别可配置，但切换应是显式配置变化。当前没有应用内部多厂商熔断、负载均衡或透明模型降级。

#### R169 重试有哪些具体边界

普通 JSON HTTP 对 429、502、503、504 最多三次，优先数值 Retry-After 且最多等十秒，否则指数退避；网络异常直接分类报错，其他状态不普遍重试。没有随机 jitter 和完整 HTTP-date Retry-After 支持。流式生成不自动重放，避免部分输出后重复内容和计费。

#### R170 并发控制在哪里

在线 API 跨请求共享 LLM Semaphore(3) 和 Embedding Semaphore(2)，每请求 Models 独立记录用量，BM25 索引共享。Worker 使用自己的 Models，评测又是独立进程，因此不是全系统全局限流；Rerank 的普通 post 也没有独立 semaphore。不能用这两个数推出系统支持的并发容量。

#### R171 模型客户端是否全局复用

Worker 生命周期内复用客户端；在线每请求新建 Models/AsyncClient，结束关闭，只把信号量与索引共享。这样隔离用量，但连接复用范围有限、可能增加 TLS 建连成本。扩展可共享传输客户端并保持请求级用量上下文，需验证并发正确性。

#### R172 流终态和用量怎么处理

读取 SSE data，正文仅转 delta.content，不把 reasoning_content 当答案；记录可用 usage，要求 stop 与 DONE。usage 可能在末尾出现，提前中断可导致未知，不能补零。结构化任务要求完整 stop，返回数组或坏 JSON 都失败。

#### R173 为什么 temperature 为零仍可能不一致

零温度减少采样随机性，不固定供应商权重、硬件、服务策略和数值计算。要保存路由、配置、Prompt、知识和运行时间，必要时重复运行分析波动，不能声称同输入必然字节级相同。固定 seed 主要控制本地实验顺序和盲审映射。

#### R174 当前网关复现还有什么盲点

应用清单可记录 gateway 及别名，但不天然固定网关底层模型或配置版本；Embedding 的本地模型身份也可能与别名实际映射脱节。预算方案要求运行前核对真实路由和配置，仍应将其升级成可自动检查的模型身份契约，不能仅凭别名宣称完全复现。

### 数据存储 部署与工程验证

#### R175 核心表之间什么关系

knowledge_base 下有逻辑 document，document 有多个不可变 document_version，每版本有 chunks；document.active_version 指当前发布版本，snapshots 保存某库版本集合；ingestion_job 对应版本。session 属于用户并保存范围，message 保存请求、状态、答案、引用及追踪，授权由用户组及文档 grants 关联。

#### R176 数据库有哪些关键约束

版本切片 UNIQUE(version_id, ordinal)，导入任务 version_id 唯一，快照 UNIQUE(kb_id, revision)，消息 UNIQUE(session_id, request_id)，以及 generating 的部分唯一索引。约束让并发冲突由权威存储裁决，但并未覆盖文件重复、文档严格全序等所有业务不变量。

embedding 列定义为不带固定维度的 vector，当前维度一致性主要由适配器和 corpus 检查保障，并非数据库 vector(1024) 自动保证所有写入。若增加表达式或分区 ANN 索引，需要同时约束模型、维度及过滤条件，避免绕过应用校验的数据破坏查询。

#### R178 数据库连接怎样使用

Go 使用 pgxpool 上限 10；Python Store 当前每次 connect 新建 psycopg 异步连接，未使用 psycopg_pool，并设置 prepare_threshold=None。后者简单但连接开销可能较大。优化前应观察活跃连接、等待和查询耗时，不能以“异步”推断连接成本不存在。

#### R179 内存 BM25 的性能瓶颈是什么

corpus 会把授权快照文本加载到内存，首次建索引需要 jieba 分词，get_scores 在进程内计算；同步 CPU 工作可能阻塞 asyncio。当前数百块可接受，规模扩大后要考虑线程/进程隔离、预构建索引或独立检索服务，并测缓存失效后的冷启动。

#### R180 Compose 怎样保护数据和端口

数据库及 uploads 使用命名卷，Go 与 Python 共享路径且 Python 只读；Web 和数据库映射仅绑定回环，Go/RAG 不直接发布主机端口。容器重建不应删除卷。Compose 的数据库演示账号、健康检查与网络隔离不等于生产最小权限或高可用部署。

#### R184 测试分层怎样组织

纯函数和适配器单测覆盖切片、RRF、向量对齐、引用、范围及评测；本地假模型加真实 PostgreSQL 做跨服务契约；浏览器验证登录、流渲染和引用；真实模型协议探测证明接口可用；冻结集和人工裁决证明特定范围的质量。每层回答不同问题，不能互相替代。

#### R185 CI 为什么不默认跑真实模型

费用、凭据、网络与模型波动会让每次代码检查不可控。当前 CI 使用虚构素材及本地假模型，跑 Go test/vet/build、Python、Vue 构建、跨服务和 Compose 冒烟。配置存在不代表本轮已执行远程 CI；真实质量评测另需冻结条件及授权预算。

### 关键故障窗口与改进顺序

#### R189 新文档导入一半时服务器重启

原 active_version 未切换，旧知识继续提供服务；处理中任务等租约过期后重新领取，旧 owner 发布前会被校验拦住。重新计算可能增加 Embedding 费用；若文件丢失则失败，不能靠租约恢复原文件。需要同时检查任务、版本和文件持久化。

#### R190 新版本发布时用户正在问旧版本

已绑定快照的请求继续按旧版本取证，之后请求读取新快照；引用保存版本和节选。普通更新提供的是快照一致性，不强制让在途请求立即切新版本；若是保密撤权则通过授权 revision 另行中止，不混用两种语义。

#### R191 模型回答一半断网

保留已输出文字，终态为 error 或 interrupted，不发送伪造完成；Go 用独立短 context 尝试保存。不会自动从头重放模型流；用户可查历史再发新请求。已发调用可能计费且 usage 不完整，未知费用应保留未知。

#### R192 撤权与最后一段回答同时发生

在单进程内，发送读锁和变更写锁决定先后顺序：撤权生效前已放行的内容不能收回，生效后旧 revision 不能继续发送。数据库保存终态与浏览器接收仍有各自失败窗口；若扩展多实例，应重新设计并证明边界，不能沿用本地锁保证。

#### R193 数据库写失败但浏览器收到答案

当前存在终态转发后 defer 落盘失败的窗口，需用消息 ID 查日志并区分展示完成和保存成功。改进可把终态持久化放在最终确认前，再设计幂等查询恢复；跨模型调用和数据库没有分布式事务，不能承诺绝对 exactly-once。

#### R200 如果重做项目你会先改什么

先把模型真实身份、调用与评分成本、问答阶段耗时及终态持久化边界做明确；完成独立跨库开发实验，决定是否保留拆解。再按实测优化连接和索引，最后讨论多实例。保持现有冻结报告及负结果，避免边改策略边失去可比较基线。

## P2 按需查阅 局部细节与专项追问

七十题。掌握核心设计后按暴露出的知识缺口补充；文件格式、具体字段和协议边界不必抢在整体方案前介绍。

### 项目表达与局部选型

#### R004 为什么不用普通搜索或直接问大模型

搜索通常要求用户自行组合多个段落；直接问模型无法保证命中私有资料及正确适用组织。RAG 将相关证据放进上下文，再用生成能力组织答案，同时保留出处。代价是增加解析、检索、版本和评测链路，而且 RAG 仍会检错、漏事实或错误拒答，并不能自动消除幻觉。

#### R005 为什么不先微调

此项目的主要问题是获取可更新、可授权、可定位的知识。微调更适合学习任务形式、输出风格或特定行为，不便承担频繁更新的知识事实和逐文档撤权。现阶段先做 RAG 基线；若未来有稳定且足量的标注，再评估微调对路由或生成的增益，不能声称项目做过训练。

#### R006 为什么不用长上下文直接塞全文

全文方案在小资料场景可作基线，但会增加调用成本和等待，也放大跨组织混淆及无关指令的暴露面。当前按授权和范围收敛后选最多五段证据。长上下文并不保证模型能找到所有关键事实；本项目也尚未完成“全量上下文对照”，不能声称检索一定优于所有长上下文方案。

#### R008 你的个人贡献怎么回答

建议按需求取舍、数据建模、Go 业务边界、Python 编排、验证和失败分析分别讲清自己的决策。AI 辅助生成的代码和文档应如实说明；能现场解释事务、租约、RRF 和评测分母，比声称全部手写更可信。具体个人开发时长和未提供的团队分工需要本人补充。

#### R011 如何解释项目规模不大但仍有价值

小规模适合把正确性机制和实验变量控制清楚。649 切片不能证明海量检索能力，但足以暴露证据组合、跨组织、版本切换和撤权问题。展示价值应落在可复现的工程与分析能力，容量扩展另用实验验证。

#### R012 如果问有没有上线

Windows 原生与本地 Docker 已有运行和持久化验证。仓库云部署记录只证明基础环境、镜像和备份准备，应用启动、迁移及 HTTPS 仍待验收；不能把配置文件或服务器准备说成正式线上服务。本轮不依据旧材料推断云端当前运行状态。

#### R015 为什么选择 Gin 和 FastAPI

Gin 的路由、中间件、鉴权和流响应足以覆盖当前业务，pgx 直接表达事务和 SQL。FastAPI 用 Pydantic 约束内部请求，配合异步 HTTP 和生命周期 Worker。没有做同负载框架性能对比，不能把框架选择讲成经过实测的性能最优。

#### R023 为什么 Vue 3 而不是复杂前端框架组合

页面核心是问答、管理、版本切片及授权，Vue 3 加 TypeScript 足够。前端需要正确处理流、状态和引用，而不是堆图表或状态库。当前直接呈现文本并提供引用，不应声称实现了完整 Markdown 富文本渲染、SSR 或复杂前端权限系统。

### 文件处理与检索实现细节

#### R029 上传如何防路径穿越和覆盖

不使用用户文件名拼保存路径，采用随机版本 ID 加白名单后缀，使用 `O_EXCL` 创建，原始文件名只作展示。Go 限制请求体约 21 MiB、文件 20 MiB，异常时清理本次文件。扩展名白名单不等于完整内容安全检查，解析器失败仍是必要防线。

#### R030 原文件和 SQL 能原子提交吗

不能。当前先保存文件，再写数据库；事务失败时 defer 删除文件。进程在文件落盘后、SQL 提交前崩溃仍可能留下孤儿文件，且没有跨文件系统与 SQL 的原子事务。可扩展为临时区、校验后发布和按引用扫描清理，但当前未实现完整垃圾回收。

#### R031 重复文件怎么识别

按知识库和原文件 SHA256 查询已有版本，重复时返回 409，用户显式确认后允许继续。它是交互提醒，不是数据库唯一约束，不能保证并发上传绝无重复，也不能识别“改格式但语义相同”。不同库允许相同内容有不同组织和权限。

#### R033 DOCX 压缩炸弹和加密 PDF 怎么处理

DOCX 先检查 ZIP 声明的解压总大小，超过 100 MiB 拒绝；加密 PDF 拒绝。提取文本过少则提示扫描件需 OCR。这些是基础约束，不构成沙箱解析体系；超时隔离、CPU/内存配额和恶意文件扫描可作为后续设计。

#### R037 为什么不直接按 token 切

字符区间更容易对应原文和评测锚点，但字符数不能精确约束模型 token。后续可在保留原文偏移的前提下增加 tokenizer 预算与句子边界，避免只改切片而破坏出处。当前 8000 正文字符也不等于整个 Prompt 的 token 上限。

#### R046 老版本晚完成会覆盖新版本吗

active_version 的条件更新比较文档版本 created_at，只有不晚于本版本的有效指针才允许切换，防止通常的旧任务晚完成。若追问严格全序，时间戳相同的边界及显式版本序号值得加强；不能宣称当前实现拥有独立单调文档版本号的 fencing 机制。

#### R048 新版失败、原文件损坏、重启分别怎样

新版失败保留旧 active_version；Worker 读取前重新计算原文件哈希，变化则失败；重启后过期租约可恢复，Go 将旧 generating 消息标 interrupted。故障恢复依赖数据库与文件都持久保存，没有承诺硬盘损坏或任意数据库丢失时零数据损失。

#### R051 中文分词做了哪些工作

使用 jieba.lcut 后转小写、过滤空白；目前没有自建领域词典、专门停用词表、同义词库或查询扩展。VPN、命令参数、组织别名可能受分词影响，排查时要看真实 token 及逐词得分，不能只说“用了中文分词所以没问题”。

#### R056 1024 维有什么代价

维度是当前 Embedding 配置，约需 4096 字节的单精度向量值，尚不含 PostgreSQL 行、页和索引开销。649 条向量值约 2.54 MiB，一百万条约 3.81 GiB，均只是理论原始值。维度更大不保证业务更好，应测效果与资源成本，项目未做维度消融。

#### R063 重排返回顺序和数量异常怎么办

检查每项 index 的类型、范围与唯一性，以及分数有限性，要求返回数量等于期望值，再按分数排序映射候选。错误明确失败，不能静默忽略重排后仍将结果记为 D。跨库要求返回全候选排序，旧单库只请求五项，所以历史缺少其余名次。

#### R067 为什么标题和章节很重要

“取消这个选项”等短段落的含义依赖上级流程。当前生成证据包括文档 title 和 locator.section，跨库再附组织元数据，避免把其他流程步骤套进答案。但 BM25 的分词索引仍只用切片正文，不能说已实现标题加权检索。

#### R069 为什么完整证据覆盖和答案正确率不一样

部分题可用黄金锚点之外的等价表述答对；反过来证据齐全也可能漏写事实。30 题候选并集及 RRF 完整覆盖各为 25/30，最终上下文为 20/30，人工通过为 22/30。三道人工通过题未完整命中指定锚点，一道锚点完整却没答对。

#### R071 零分候选会被过滤吗

当前 BM25 按分数取 Top-20，没有相关性阈值；向量也返回最近项，不等于存在可靠答案。因此“返回了五条”不能作为足够证据，后续充分性判断与拒答样本非常重要。增设阈值需要先标定，不能随意筛掉困难正例。

### 跨库及生成的特殊边界

#### R080 用户问未收录组织怎么办

范围理解要求拒答并说明缺少对应组织资料，不能拿最相似学校替代。显式比较多个组织则按对象收集证据，缺少必要对象不输出完整比较。单库快捷路径并不是完整组织识别器，仍依靠后续证据判定避免错用。

#### R083 为什么最多比较五库

最终证据上限是五段，更多比较对象无法保证至少一段对应来源，因此要求缩小范围。指定检索库最多 32 与比较对象最多 5 是不同限制，前者控制请求范围，后者控制回答证据分配。

#### R084 用户改变学校或引入年份怎么办

范围理解以本轮明确条件优先，结合历史消解指代；年份或条件会改变结论但信息不足时澄清。文档上传时间不等于制度生效时间，历史材料也不能自动宣称当前有效。当前没有独立政策有效期知识图谱。

#### R085 如何测试多轮而不高估

固定 history 重放检验某一轮理解；真实 Go 会话链还会受前轮完成状态、历史过滤、撤权和持久化影响，需要独立联测。当前新 40 题的多轮部分采用固定历史，不能把它说成全链用户会话成功率。

#### R086 多库执行是否已经并行

当前逐查询生成向量、逐库执行召回，未用 gather 将所有库搜索并行化。复用向量能减少外部调用，但库数量增加仍增加 SQL 和内存处理。未来可做有界并行和取消传播，必须同时验证连接池与提供商限流。

#### R089 充分性判断返回了编号就一定可信吗

程序验证行为枚举、原因类型、编号白名单，answer 必须有编号。但它没有形式化证明必要事实齐全，也没有保证选中的编号被生成逐事实正确使用。判定分支的格式校验和语义质量是两个层次。

#### R092 没引用、伪造引用、长度截断分别怎样

没引用或编号非法在最终验证失败；流只在收到 `[DONE]` 且 finish_reason=stop 时接受完整结束，length 等终态失败。已流出的文字保留为未验证/error，不能把 HTTP 200 或有正文当作回答成功。

#### R093 为什么流完才校验引用

完整答案出来后才能检查最终标签和比较对象覆盖，用户可先看到增量以改善体验。代价是失败前可能已看到不可靠文本。可扩展为先缓冲完整答案再展示，或逐段验证，但会增加首字等待、调用或协议复杂度；当前没有逐段语义验证。

#### R094 引用快照为什么不只存原文件链接

文件可能更新或停用，历史回答需要保留当时文档版本、切片、原文节选、定位和标签。当前引用数据保存正文等快照字段，原文件下载仍需当前授权。这样能解释历史来源，但不是永久越权读取许可。

#### R095 为什么要保留标题 组织和来源信息

用于区分不同学校和流程，帮助用户核对范围；引用卡片也便于追溯。元数据同样可能泄漏受限资源，因此要在模型理解前先做授权过滤。当前应用层授权不是数据库 RLS，所有内部访问路径都需保持边界。

#### R096 忠实回答和正确回答有何不同

忠实表示结论得到给定上下文支持，正确还要求回答用户真正的问题、适用范围正确且覆盖必要事实。上下文选错但照着说可能忠实而不正确；只有部分正确事实也可能遗漏关键步骤。Ragas 忠实度不能代替正式答案正确率。

#### R097 如何处理证据冲突

先看组织、年份、方案和前置条件，避免把条件不同误判为冲突；真正矛盾且无法裁定时澄清或说明资料不足。当前新题中四道是条件辨析，并没有经确认的四道真实矛盾材料，不能夸大冲突处理覆盖。

### 流协议与安全实现细节

#### R104 一条流有哪些事件

正常有 status、evidence、answer_delta、citations、done；拒答/澄清走 evidence、refusal、done；故障走 error。Go 为转发事件补 request_id、seq、message_id。seq 是流内递增序号，没有配套持久事件日志，不能据此宣称支持 Last-Event-ID 续传。

#### R107 前端如何处理半包和中文

TextDecoder 以流模式解码，缓冲未完成片段，按空行切 SSE 帧，再收集 data 行解析 JSON。中文 UTF-8 可能跨网络块，不能对每块单独转字符串。当前是受控内部协议解析器，不应说已实现 SSE 标准全部字段与所有边界测试。

#### R108 为什么 Nginx 配置影响首字

代理缓冲会让上游逐字输出在浏览器端变成批量出现，因此关闭 proxy_buffering，并设置 X-Accel-Buffering=no 和合理读取超时。客户端也要及时渲染响应式对象。浏览器首字包含网络、代理和渲染，与 Python server_ttft 不同。

#### R110 会不会出现慢客户端拖住撤权

send 在授权读锁内检查 revision 并写出、Flush，慢连接可能延长持锁时间；当前写超时提供有限边界。可优化为更精细的发送协调和写入期限，但不能在释放锁后无保护地发送，从而失去撤权线性化边界。该权衡尚未做压力测试。

#### R112 还有哪些 Go 工程点会被追问

pgxpool.MaxConns=10，游标需及时关闭；密码 bcrypt，令牌随机生成后只存 SHA256；请求体限长，SQL 参数化；context 取消向上游传播，错误信息不带密钥。当前没实现完整优雅退出、分布式 tracing、连接池自适应或生产限流，面试需区分已有代码和改进方案。

#### R114 为什么不选 JWT

当前需要即时禁用和撤销，数据库令牌简单直接；代价是每次鉴权依赖数据库。JWT 可减少查库，但撤销、角色更新仍需版本或黑名单。不能将“用了 JWT”当作更安全的默认答案，也不能编造项目已有 JWT。

#### R116 为什么旧资料和新文档默认不同

升级需要兼容已有演示资料，同时新导入采用保守默认。schema 迁移记录及审计保留这次规则转换，不能反复把所有新文档设回 all_users。迁移兼容不意味着新资料默认公开。

#### R118 BM25 缓存怎样避免跨用户污染

授权限制后的快照身份包含可见版本集合及授权 revision，缓存按成员或快照 ID 区分，不按裸知识库 ID 共用索引。当前最多八项，按插入顺序淘汰，命中不刷新，因此是近似 FIFO 而非严格 LRU。权限频繁变化可能引发重建开销。

#### R123 历史依赖是精确的已引用文档吗

当前新消息 provenance 记录请求范围内当时可见的文档集合，是保守依赖，不仅是最终引用集合。因此撤销一个未被最终引用但在范围内的文档，也可能隐藏整条回答。这样较安全却可能过度遮蔽；缩小到实际模型输入还需覆盖路由与历史依赖。

#### R124 旧消息缺 provenance 怎么办

尝试从 snapshot_id 和 trace 中恢复版本及文档集合，再按当前权限检查；无法恢复则隐藏，不默认允许。不能仅检查最终一个引用，因为旧回答可能受未引用上下文影响。保守迁移策略需要解释其可用性代价。

#### R126 原文件下载和错误码怎么保护

下载按版本联接文档并执行当前授权，不直接暴露文件卷 URL；使用附件及 nosniff。未授权和不存在尽量给一致响应，减少枚举。具体接口不完全一致：文件为 404，会话创建非法范围为 400；不能把全部接口概括为统一 404。

#### R127 前端令牌和 XSS 风险如何回答

token 存 sessionStorage，缩短跨标签或长期落盘范围，但同源 XSS 仍能读取。当前模板文本展示有助于避免直接执行模型 HTML，不应声称彻底防 XSS。HttpOnly Cookie 是可选改进，但会引入 CSRF、SameSite 和跨域策略的设计。

#### R129 日志 审计和隐私如何处理

权限变更记录 actor、action、target 和 details；提供商公共错误只保留分类及状态，避免透出原请求。细节 trace、原文、实际答案和评测材料保存在忽略目录。当前消息 trace 含授权后的详细候选，若面向生产还需最小化返回、分级可见性、脱敏和保留期。

### 指标 实验与预算细节

#### R132 D 比 A 提高多少

检索平均 Recall@5 的绝对差为 15.83 个百分点，辅助答案正确率绝对差为 23.75 个百分点。后者不能称为两组都经人工裁决的提升；也不能把百分点和相对百分比混用。若算相对提升，必须明确基线和指标，不宜在简历中隐藏分母。

#### R134 Full coverage 和 MRR 怎么定义

Full coverage 要求同题所有必要证据组命中；MRR 寻找前 k 段累计首次覆盖任一完整锚点的最早位置，再取倒数。此 MRR 不是“全部证据首次齐全”的倒数，不能用它替代完整覆盖。拒答和澄清题的这三项指标为 null。

#### R138 新 40 题的组成及限制

10 开发、30 测试，共 27 回答、8 澄清、5 拒答；场景包括比较 12、歧义 8、多轮 8、条件辨析 4、无答案 4、正常对照 4。25 题与旧题共享来源段落，四道条件辨析不是真实矛盾集；固定历史多轮也不是完整会话链。

#### R139 六项权限协议为什么单列

分别验证跨库可见性、同库文档、默认范围、未授权指定范围、历史撤权和在途撤权。它们关注不该进入模型或用户输出的数据，不是知识题答对。因此独立报告 6/6 工程边界，不能加到 40 题正确率分母里。

#### R144 引用合法率 100% 是不是每题有引用

不是。合法率是实际出现的引用中编号与来源合法的比例，没有引用的答案不进入该分母；回答引用覆盖率才反映可回答题是否完整结束并包含合法引用。旧 D 端到端报告引用合法率 100%、回答引用覆盖率 96.875%，两者不能合并成“全部回答都有正确来源”。

#### R148 样本这么少如何解释统计可信度

报告分子分母、场景及题目相关性，比较同题改善与退步；若做区间可按事实主题或会话聚类 bootstrap，检验二元配对可考虑 McNemar。当前工具不等于已经做过显著性检验，也不能把多次改写当独立样本制造很窄区间。

#### R149 什么情况下会重新发布评测集

原文变化、标准事实或来源锚点修订、主题划分改变，需要新修订与人工审核，再冻结为新版本。保留旧清单、答案和裁决，不在原目录覆盖。不同环境重新导入产生新 ID 时需重新映射核对，不能直接拿原生冻结清单套 Docker 数据。

#### R152 trace 具体记录什么

候选 ID、融合及淘汰、逐库逐查询列表、返回的重排索引分数、选择顺序、Top-K/预算淘汰原因、正文占用、重复文本 ID、最终上下文哈希及分阶段耗时。旧单库重排只返回五项，trace 的 rerank_complete 能区分是否完整。

#### R153 有了 trace 就能证明因果吗

不能。trace 可以确认某证据在哪步消失，不能直接证明替换算法后整体答案会变好。真正因果比较需固定其他变量做成对实验，允许零收益和退步。黄金锚点缺失也不能自动推出不存在语义等价证据。

#### R156 为什么要求连续原文片段

用程序校验限制拆解模型添加组织、年份、操作和事实，减少语义漂移。它也会漏掉需要语义改写才能拆开的表达，是主动收紧的实验能力边界。关键词触发可能有漏检，不应描述为成熟通用规划器。

#### R158 拆解增加多少成本

每道触发的复合题新增最多一次拆解及两次子查询 Embedding，即不含重试最多三次模型 HTTP 请求；复用原查询向量仍需相应基础请求，逐库 SQL 也随子查询增加。不是“多生成两个答案”，也没有当前实测收益或费用结论。

#### R159 为什么逐题交错执行

先跑完基线再跑候选会混入服务时段、网络和模型变更影响。固定 seed 决定题序与每题先后，让两策略更接近地运行。交错不能冻结供应商内部权重，但减少系统性顺序偏差，应同时记录实际路由和配置。

#### R161 请求硬预算怎样持久化

每次出站前记录 started，包含题目、阶段与 attempt；两策略共享 HTTP 上限，续跑扣除历史已发请求。正常重试和辅助评分也消耗预算。日志 flush 不等于完成 fsync 级耐久证明，当前机制不能夸大为掉电情况下绝无账本缺口。

#### R162 调用次数为什么不等于金额

每次 token 长度、输入输出计价、缓存及厂商规则不同。模型用量缺失记未知，孤立 started 没结果时费用完整性为 false，不能当零。当前开发提案为 150 次 HTTP、约 1–3 元估算且仍待单独预算确认，不是已支付费用或金额硬封顶。

#### R163 为什么不能一直续跑到答对

这样会把一次随机失败隐藏成最好样本，产生选择偏差并漏算资源。新 scope 续跑保留已落盘终态，未执行为 pending；故障修复另开有版本的运行。负结果和退步也必须保留，而不是为了简历指标强行发布实验策略。

#### R164 新优化现在做到哪一步

代码、替身模型、独立 Go/Python/SQL 联测及审核工具已验收，40 题和六项权限协议已审核冻结；最新记录为 Python 82 项通过。真实开发实验未运行，随后才可能锁策略、跑正式集、人工裁决。不能把工具能执行写成质量已提升。

### 模型协议 运维与现场练习

#### R166 直连和网关协议有哪些差异

直连 Embedding/Rerank 使用厂商嵌套 input/parameters 结构；网关 embeddings 使用 input、dimensions，rerank 使用 query/documents/top_n 等扁平字段，返回索引字段也不同。chat、embedding、rerank 是路由别名，不能把别名当真实模型版本。

#### R168 私有 CA 和隧道怎样处理 TLS

创建 SSLContext 并加载配置的 CA，不禁用验证；若容器连接宿主机隧道，可变更 TCP 连接 host，同时保留逻辑 Host 和 SNI。网关地址要求 HTTPS 且根路径为 /v1，拒绝 userinfo、query、fragment，禁用环境代理继承和自动重定向。连接位置和证书身份必须分开解释。

#### R177 JSONB 为什么这么多

locator、版本集合、引用及 trace 形态灵活，JSONB 便于保存不可变快照和诊断记录。代价是数据库类型约束较弱、复杂检索不便、字段容易膨胀。稳定业务关系如用户组仍用关系表；大规模 trace 可分离归档，而不把所有内容无限塞消息表。

#### R181 健康检查能证明什么

Go/RAG health 主要检查数据库可达，Web 检查静态入口；depends_on 帮助控制启动次序，restart 处理进程退出。它们不能证明模型权限、知识可检索、流协议或答案质量正常，也不自动迁移数据或触发业务回滚。

#### R186 Windows 开发踩过什么真实问题

根 .env 读取曾因多个候选路径的加载行为而未生效，已有回归测试；Windows Python 异步循环与 psycopg 兼容需要启动入口处理；本机原生和 Docker 数据库端口、卷与 ID 不同，必须分清。可展开为配置优先级及环境隔离，不把平台问题包装成模型算法优化。

#### R187 CI 后台进程锁如何讲

已有维护说明指出常驻 uv run 可能持有缓存锁，退出时清理失败；当前流程使用已建虚拟环境解释器启动服务，exec 记录 PID，并在 EXIT trap 中 kill 后 wait。它解释进程生命周期问题，不能代替 RAG 质量成果；远程 PR 状态需当场另查。

#### R198 现场最可能要求手写哪些代码

优先练 RRF 的稳定合并、带字符区间的覆盖判断、SQL 任务领取和租约发布校验、单会话部分唯一索引、SSE 半包解析、context 取消后独立落终态、合法引用映射。写完应主动给重复、并发、越权、截断和空输入反例，而非只展示正常路径。

#### R199 面试官质疑你只是接 API 怎么回答

承认没有训练模型；价值在应用正确性与可验证性。用一个实际窗口展开：新版处理失败仍保旧，或者撤权与流输出通过 revision/锁协调，或者从八道失败里定位五道候选缺失并设计单变量实验。能解释失败、代价和剩余漏洞，比堆技术名词更能证明工程能力。
